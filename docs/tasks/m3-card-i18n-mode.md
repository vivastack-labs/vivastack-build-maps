## T3-01 東京からの距離

- **種別**：feat
- **依存関係**：T1-08、T2-02
- **目的**：東京からの距離を、固定値ではなく緯度経度から計算して表示する。
- **参照仕様**：F-CARD-03、7.5

### 実装内容

- `src/lib/distance.ts`：
  - ハバーサイン公式で、2点の直線距離（km）を計算する（地球の半径 6,371km）。
  - 10km単位に丸める。
- 表示：`Intl.NumberFormat` と辞書の文言で「約 820 km」のように3言語で表示する。
- 基準の点は、東京都のYAMLの県庁の緯度経度を使う。値はビルド時に計算する。

### 完了条件

- `src/lib/distance.ts` のカバレッジが90%以上。

### テスト条件

- 単体：
  - 同じ点どうしは0km。
  - 東京都庁 → 大阪府庁、東京都庁 → 沖縄県庁の距離が、国土地理院の距離計算の結果と1%以内で一致する（7.5）。
  - 丸め：394km → 390km、395km → 400km。
  - 3言語の表示。1,000km以上では桁区切りが入る。

## T3-02 本番用・プレビュー用のコンテンツの絞り込み

- **種別**：feat
- **依存関係**：T1-07、T2-04、T2-09、T2-10
- **目的**：本番には人が確認した内容だけを出し、プレビューではレビューのためにすべてを確かめられるようにする。
- **参照仕様**：7.1、4.11.4、R1

### 実装内容

- 環境変数 `BUILD_TARGET`（`production` / `preview`）で、ビルドの種類を切り替える。`pnpm build` は `production`、`pnpm build:preview` は `preview`。
- `src/lib/publish.ts`：
  - 本番：名物・名所・行き方のすべての項目が `reviewed` の県だけ、その内容を出す。そうでない県（未作成を含む）は「準備中」にする。
  - プレビュー：すべての項目を出し、`reviewed` でない項目に「下書き」の印を付ける。
- 「準備中」の表示（4.11.4）：地図は灰色の斜線、凡例に「準備中」、さくいんの県名に「（準備中）」、ツールチップ（T2-09）は県名だけ。
  - T2-09 で分かったこと：ツールチップ（`MapTooltip`。`src/components/`）は、渡された県の `specialties` が空なら県名だけを出す（名物の `status` は見ない。T2-09 は名物をすべて出す）。したがって、`publish.ts` の結果（準備中の県は名物を空にしたもの）を `MapTooltip` の `prefectures` に渡せば、「準備中」の県のツールチップは県名だけになる。`MapArea` に渡す `prefectures` を `publish.ts` の結果にすることで足りる。

### 完了条件

- 本番用のビルドに、`reviewed` でない項目の文が含まれない。

### テスト条件

- 単体（`publish.ts`）：
  - 全項目が `reviewed` の県 → 内容を出す。
  - 1項目だけ `verified` の県 → 本番では「準備中」になり、名物・名所・行き方を1つも含まない（7.1）。
  - 名物・名所が空（未作成）の県 → 本番では「準備中」。
  - プレビューでは、すべての項目を出し、`reviewed` でない項目に「下書き」の印が付く。
- E2E（`tests/fixtures/content/` を使う）：
  - 本番用のビルド：「準備中」の県が斜線で塗られ、凡例に「準備中」、さくいんに「（準備中）」が出る。ツールチップは県名だけ（4.11.4）。
  - 本番用のビルドのHTMLに、`verified` の項目の文が含まれない（R1）。
  - プレビュー用のビルド：すべての県が地方の色で塗られる。

## T3-03 県のカード

- **種別**：feat
- **依存関係**：T2-05、T3-01、T3-02
- **目的**：47県分のカードをHTMLに出しておき、JavaScriptは表示する県を切り替えるだけにする。JavaScriptのサイズを増やさずに、全コンテンツを最初の表示から使えるようにする。
- **参照仕様**：F-CARD-02〜06・08、4.11.4、4.11.7、6.6 (2)、D24、F-MODE-04

### 実装内容

- T2-08 で分かったこと：「市区町村の一覧」は `MuniList`（`src/components/`。クライアントコンポーネント）が、`CardArea` の `CardSwitch` の下に1つだけ置いてある（最大化中で読み込めたときだけ `<details data-muni-list>` を出す。props は文言と言語だけで、県の内容は渡さない）。`PrefCard` に置き換えるとき、`MuniList` を 47 枚のカードの中に入れると、非表示のカードにもフックと一覧が47個できる。4.11.7 の順（最大化ボタンの後）にするなら、`CardSwitch` の外、`PrefCard` の下に残すか、最大化中の県のカードだけに入れる。
- `src/components/PrefCard.tsx`（サーバーコンポーネント）を47県分出力し、`id="pref-NN"` と `hidden` を付ける。
- カードの中身（4.11.7 の順）：見出し（地方名・県名・県庁所在地）、東京からの距離、行き方（交通手段・経路・所要時間。「目安」と書く）、名物3つ（絵文字・名前・解説）、名所3つ、最大化ボタン（「大きくして市区町村を見る」／「元の大きさにもどす」）、市区町村の一覧（T2-08）。解説文は `ModeText` でこども向け・おとな向けの両方を出す。
- 「準備中」の県のカード：県名、県庁所在地、距離と「名物・名所は準備中です」（4.11.4）。
  - T3-02 で分かったこと：`CardArea` の `prefectures` は `publish.ts` の結果（`PublishedPrefecture`）。`pending` が `true` の県が「準備中」で、名物・名所は空・`access` はない（本番）。文言は辞書の `comingSoon.card`（`{ kids, adult }` なので `ModeText`）が既にある。
- プレビューでは、「下書き」の項目に印を表示する。
  - T3-02 で分かったこと：`PublishedPrefecture` の `access`・`specialties[]`・`spots[]` の各項目に `draft: boolean`（`status !== 'reviewed'`）が付いている（本番の内容を出す県は、すべて `false`）。プレビューでは `pending` が常に `false`。印の文言は T3-03 で辞書に足す。
- T3-01 で、仮のカード（`CardArea` の `<div data-card-pref hidden>`）に距離の行（`<p data-card-distance>`。`distanceText(lang, distanceOf(distances, code))`（距離がない県は例外にする `distanceOf` も一緒に移す）。`distances` は `page.tsx` が `distancesFromTokyo()` で1回だけ求める）を足してある。東京都（`TOKYO_CODE`）のカードは基準の点なので、距離の行を出さない（F-CARD-03 は東京都庁から県庁所在地まで）。`PrefCard` の「東京からの距離」には、この行をそのまま移す（`data-card-distance` と、`CardArea` の `distances` の props、`CardArea.test.tsx` の距離のテストも合わせる）。
  - `distanceText`（辞書に依存）を `PrefCard` 側か `src/i18n/` に移し、`distance.ts` を計算だけにするかを T3-03 で決める。
- T2-05 の仮の表示を置き換え、表示する県のカードの `hidden` を外す。
  - 切り替えの仕組みは T2-05 の `CardSwitch`（`'use client'`）と `applyCardState`（`src/features/map/mapDom.ts`）をそのまま使う。`CardArea` の仮の `<p data-card-pref="NN" hidden>`（県名だけ）を、`PrefCard`（`data-card-pref="NN"` と `hidden` を付ける）に置き換える。案内文（`data-card-guide`）は残し、県がないときだけ見せる。`CardSwitch` の中に置けば、クライアントの変更は要らない。
  - Tailwind v4 の preflight は `[hidden]` を `display: none !important` にする（`node_modules/tailwindcss/preflight.css`）。JavaScript なしで `:target` のカードを見せるには、`[data-card-pref]:target { display: block !important }` のような `!important` 付きの規則が要る。
- JavaScriptがないとき：CSS の `:target` で、ハッシュの県のカードを表示する。
- カードの内容をクライアントコンポーネントの props に渡さない（6.6 (2)）。
- 本物のカードが画面より高くなると、sticky のままでは下が見えない。`lg:max-h-[calc(100dvh-2rem)] lg:overflow-y-auto` などで、カードの中をスクロールできるようにする（T2-03 の `CardArea` は 1024px以上で sticky）。

### 完了条件

- カードの解説文が、HTMLの本体に1回・RSC のデータに1回だけ出てきて、ほかの言語の文と、ふりがなの記法つきの元の文字列（`{漢字|よみ}`）は出てこない（カードをクライアントコンポーネントにして props で渡すと、元データが入る）。
  - 最初の完了条件は「HTMLの中で1回だけ」だったが、App Router はサーバーコンポーネントの結果を必ずRSCのデータ（HTMLの末尾の `<script>`）にも入れるので、満たせない（T3-03 で実測：`dist/en/index.html` に2回）。開発概要書 6.6 (2)・D24 を事実に合わせた。

### テスト条件

- コンポーネント（`PrefCard`）：
  - 見出し、距離、行き方と「目安」、名物3つ（絵文字・名前・解説）、名所3つが出る（F-CARD-02〜06）。
  - 「準備中」の県では、名物・名所・行き方の代わりに「名物・名所は準備中です」が出る（4.11.4）。
  - 解説文は、こども向けとおとな向けの両方が出る（F-MODE-04）。
  - 「下書き」の印は、`draft` の項目にだけ出る（7.1）。最大化ボタンは `hidden` で出力され、両方の文言を持つ（F-CARD-08）。
- E2E：
  - ホバー・固定で、表示されるカードが切り替わる（F-CARD-01・07）。
  - 最大化ボタンで最大化し、ボタンの文言が「元の大きさにもどす」に変わる（F-CARD-08）。
  - JavaScriptを無効にして `/ja/#pref-13` を開くと、東京都のカードが表示される（6.6 (2)）。
- ビルドの出力：ある解説文の文字列が、出力したHTMLの中に、`<script>` の外に1回、`<script>`（RSCのデータ）の中に1回だけ出てくる。英語のページには同じ名物の日本語・中国語の解説文が、日本語のページにはふりがなの記法つきの元の文字列が、出てこない（D24）。
- E2E：JavaScript があるとき、`/en/#pref-13` を開いてもハイドレーションの後は案内文だけが見え、固定した県のカードだけが見える（`:target` の規則が止まる。6.6 (2)）。

## T3-04 出典の表示

- **種別**：feat
- **依存関係**：T3-03
- **目的**：内容の根拠をたどれるようにし、AIで作成して人が確認していることを明示する。
- **参照仕様**：F-SRC-01〜04、8.3

- T3-03 で分かったこと：「市区町村の一覧」（`MuniList`）は、47枚のカードの中ではなく、`CardArea` の `CardSwitch` の外、カードの下に1つだけ置いてある（カードの中に入れると、クライアントコンポーネントが47個できるため）。出典（`<details>`）を `PrefCard` の中に入れると、4.11.7 の順（最大化ボタン → 市区町村の一覧 → 出典）で、出典が一覧より上になる。守るなら、出典だけを `PrefCard` の外の2つ目の `[data-card-pref]` の組にして `CardSwitch` で切り替える、一覧と出典の位置を入れ替える、などで解決する。

- フッター（T2-03 の `Footer`。中身は空）：地図データの出典（8.3 の文。3言語）、「AIで作成し、人が確認しています」。「このサイトについて」・プライバシーポリシーへのリンクは T4-05 で加える。

  - 出典のタイトルのふりがなは日本語のページだけに出し、en・zh のページは `plainText()` にする（タイトルに `lang` は付けない）。
  - フッターには、地図データの出典（国土数値情報）と AI の明記だけを載せた。読みがな（総務省）・県庁の位置（地理院地図）の出典は、T4-05 の「このサイトについて」に載せる。

### 完了条件

- 出典のある項目・ない項目の両方が、正しく表示される。

### テスト条件

  - 「出典」欄は、最初は閉じている（F-SRC-01）。

## T3-05 モード・ふりがなの切替

- **種別**：feat
- **依存関係**：T3-03
- **目的**：こども・おとな、ふりがなの切替を、表示のちらつきなく行う。JavaScriptがなくても既定のモードで読めるようにする。
- **参照仕様**：F-MODE-01〜04、6.6 (3)、D23、U1、4.11.5

### 実装内容

- 既定値を決める（開発計画 5章 U1 の推奨案）。結果を開発概要書の第16章と付録Aに書く。
- `<head>` の初期化スクリプト（500バイト未満）：localStorage の値を `<html data-mode data-ruby>` に反映する。localStorage の読み書きは try/catch で囲む。スクリプトの文字列は定数として1か所に置く（T4-01 でハッシュを計算するため）。
- ビルド時に、言語ごとの既定値を `<html>` に書いておく。
- こども向け・おとな向けの片方は `display: none` で隠す（読み上げ・`aria-live`・ボタンの名前からも除くため。`visibility` や `opacity` は使わない）。T2-07 の `MuniStatus` の失敗の文言・「再試行」ボタンも `ModeText` なので、切り替わると片方だけが読み上げられる。
- `app/globals.css`：`html[data-mode="kids"] .adult { display: none }` などの切替のルール、`html[data-ruby="off"] rt { display: none }`。`@custom-variant kids` / `adult` を定義する（D26）。
- Header（T2-03）に、モードの切替とふりがなの切替（日本語のページだけ）のボタン（`aria-pressed`）。
- T2-03 の `CardArea` の案内文は、T3-05 までおとな向け（`card.guide.adult`）だけを出している。`ModeText` に戻す。
- T3-03 で分かったこと：`PrefCard` の解説文（名物・名所）と「準備中」の文は、`ModeText` でこども向け・おとな向けの両方を出していて、T3-05 までは両方が画面に見える（PRのスクリーンショットでも2つずつ並ぶ）。上の CSS で片方が隠れることを、カードでも確かめる（E2E）。`.kids`・`.adult` の `display` を `PrefCard` の側で上書きしていない（`!important` を使わない限り、上の規則が効く）。

### 完了条件

- 開発概要書の U1 が決定になっている。

### テスト条件

- 単体：
  - 初期化スクリプトが500バイト未満（D23）。
  - localStorage が例外を投げる環境でスクリプトを実行しても、例外が外に出ず、既定値のままになる（4.11.5）。
- E2E：
  - モードを切り替えると、こども向けとおとな向けの文が入れ替わる（F-MODE-01）。
  - ふりがなを OFF にすると `rt` が見えなくなる。どちらのモードでも切り替えられる（F-MODE-02）。
  - 再読み込みしても設定が残り、最初の描画から保存した値になっている（F-MODE-03、D23）。
  - JavaScriptを無効にすると、既定のモードの文だけが見える（F-MODE-04）。
  - 英語・中国語のページには、ふりがなの切替がない。
  - localStorage を使えなくした環境でも、エラーなく表示され、切替はそのページの中で効く（4.11.5）。

## T3-06 スマホの下から出るパネル

- **種別**：feat
- **依存関係**：T3-03
- **目的**：スマホで、地図を大きく隠さずにカードを読めるようにする。
- **参照仕様**：F-MAP-05、4.11.3、4.11.6、4.11.7

### 実装内容

- T3-03 で分かったこと：1列の配置（1024px 未満）では、カードがさくいんの上にあるので、マウスでさくいんの項目にのせるとカードの高さが変わり、さくいんがずれる（E2E で、pointerdown と pointerup が別の項目になってクリックが固定にならないことがあった）。768px 未満は下から出るパネルで流れから外れるので解消する。768〜1023px のマウス操作でも起きるので、カードの高さを固定する・さくいんでのホバーではカードを変えないなどを T3-06 で検討する。
- 768px未満では、カードの領域（T2-03 の `CardArea`）を下から出るパネルにする。状態は「閉じている」「一部だけ見える（見出しと最大化ボタン）」「全部見える（画面の高さの約85%）」。
- パネルの開閉は固定の有無に合わせる。固定したら一部だけ見える状態で開き、閉じたら固定も解除する（4.11.3）。
- 開いたらフォーカスをパネルの見出しに移し、閉じたら元の県に戻す（4.11.6）。
- `prefers-reduced-motion` のときは動きを付けない。

### 完了条件

- 768px未満でだけパネルになり、768px以上では T2-03 の配置のまま。

### テスト条件

- E2E（スマホ）：
  - 県をタップすると、パネルが一部だけ見える状態で開き、見出しと最大化ボタンが見える（4.11.7）。
  - 全部見える状態にすると、パネルの高さが画面の約85%（±5%）になる（4.11.7）。
  - パネルを閉じると、固定も解除される（4.11.3）。
  - 開くとフォーカスがパネルの見出しに移り、閉じると元の県に戻る（4.11.6）。

## T3-07 言語の切替

- **種別**：feat
- **依存関係**：T3-03
- **目的**：3言語のページを、見ている県を保ったまま行き来できるようにする。検索エンジンに言語の対応を伝える。
- **参照仕様**：F-I18N-01〜03、4.11.2、D8

### 実装内容

- Header に言語切替（`/ja/`・`/en/`・`/zh/` へのリンク。今の言語に `aria-current`）。
- T3-05 で分かったこと：`<html data-mode data-ruby>` は `suppressHydrationWarning` で、初期化スクリプトが書いた値（localStorage の保存した値）を初回だけ DOM が優先する。言語を `<Link>` のソフトナビゲーションで切り替えると、React が `<html>` の属性を新しい言語の既定値（D37）に書き戻し、保存した値が消える。言語の切替は全体の読み込み（`<a>`）にするか、移った後に保存した値（`maps.mode`・`maps.ruby`）を当て直す。切替のあと、保存したモード・ふりがなが残るテストを足す。
- T3-03 で分かったこと：JS ありでハッシュつきの URL を開くと、ハイドレーションの前は `:target` のカードが見えてブラウザがそこへスクロールし、ハイドレーションの後は状態が空なのでカードが消えて案内文になる（スクロールの位置だけ残る）。開いたときのハッシュで固定するとき、ハイドレーションの前後でカードが消えないことをテスト条件に加える。
- T3-06 で分かったこと：ページを開いたときのハッシュから固定を復元すると（`restore`）、768px 未満では `CardSheet` が「閉じている → 開いた」と受け取り、フォーカスを県名の見出しへ移し、パネルを一部だけ見える状態で開く。読み込み直後にフォーカスが動くのは、読み上げ・キーボードの利用者には予想外かもしれないので、復元のときはフォーカスを移さない（`CardSheet` の `useSheetDom` で、復元による開きを見分ける）かを決める。パネルが開くこと自体はハッシュで読む内容（カード）を見せるために必要。ハイドレーションの前（JavaScript の読み込み中・失敗時）は、`:target` の県があれば `globals.css` の規則で全部見える状態の見た目になる（T3-06）。
- 固定している県をハッシュ（`#pref-NN`）に反映する（`history.replaceState`）。言語切替のリンクにハッシュを引き継ぐ。
- ページを開いたときにハッシュがあれば、その県を固定する（T2-01 のハッシュからの復元）。正しくないハッシュは無視する。
- `<head>` に `hreflang`（`ja` / `en` / `zh-Hans` / `x-default` → `ja`）と `canonical`。URLはサイトの絶対URL。

### 完了条件

- 3言語のどのページからでも、ほかの2言語に移れる。

### テスト条件

- 単体：ハッシュの解析（`#pref-13` → `13`、`#pref-99`・`#pref-1`・`#foo` → なし）。
- E2E：
  - 県を固定して英語に切り替えると、英語のページで同じ県が固定されている（4.11.2）。
  - `/en/#pref-13` を開くと、東京都が固定されている（4.11.2）。
  - 正しくないハッシュで開いても、エラーにならず、何も固定されない。
  - `<head>` に `hreflang` が4つあり、URLが正しい（F-I18N-03）。
  - 今の言語のリンクに `aria-current` が付いている。

## T3-09 最初の読み込みのサイズを基準値に収める

- **種別**：perf
- **依存関係**：T3-08
- **目的**：本番と同じ量のコンテンツでも、最初に読み込む HTML＋JavaScript＋CSS を 5.1 の基準値（gzip 後 300KB 以下）に収める。
- **参照仕様**：5.1、6.6 (2)、D24

### 実装内容

- T3-08 の実測（開発概要書 6.6 (2)）：
  - 上限のコンテンツ（`scripts/make-max-content.ts`）では、gzip 後 ja 573.5KB・en 449.4KB・zh 453.4KB で、基準値を超えた。
  - 内訳は、HTML が 265〜389KB（HTML の本体と RSC のデータにカードの内容が1回ずつ入る。gzip では重複がほとんど縮まない）、JavaScript が 178.5KB（8ファイル）、CSS が 5.9KB。
  - Lighthouse（スマホ）は、en・zh が Performance 96・LCP 2.1秒で基準値に収まった。ja は LCP 2.7秒で基準値（2.5秒）を超え、Performance は 89〜90。
- 着手時に、次の候補を調べて比べ、オーナーが決める（開発計画 5章）。
  - (a) カードの内容（名物・名所・行き方・出典）を言語ごとの JSON にし、県を選んだときに読み込む（6.6 (2) の既定の方針）。JavaScript がないときの `:target` の表示は失われる。JSON の読み込みの失敗の扱いと、CSP の `connect-src`（T4-01）も要る。
  - (b) HTML に埋め込んだまま減らす。例：RSC のデータにカードの内容が入らない描き方を調べる。最初に読み込む JavaScript（React・Next.js の実行環境・d3）を減らす。
  - (c) 5.1 の基準値を見直す。
- どの方式でも、上限のコンテンツで `pnpm size` が基準値に収まることを確かめる。

- **決めた方式（オーナーが決定。開発概要書 D38）**：(a)。カードの内容（行き方・名物・名所・出典）を、県ごと・言語ごとの JSON（`/cards/{lang}/NN.json`。`app/cards/[lang]/[file]/route.ts` がビルド時に出力）にして、県を固定したとき・ホバーしたときに読み込む（`CardDetails`）。県名・地方名・県庁所在地・距離・最大化ボタン・「準備中」の文・ツールチップは HTML に残す。JavaScript がないときは、`:target` のカードに見出しまでを出し、内容の代わりに「JavaScript を有効にすると読めます」の文を出す。読み込みの部品は市区町村（T2-07）と共通にした（`src/features/loader/`）。(b) は JavaScript の下限が約 165KB で、ja の上限が約 384KB のまま収まらなかった。(c) は採らなかった。
- 結果（上限のコンテンツ。`pnpm size`）：gzip 後 ja 269.8KB・en 260.3KB・zh 262.2KB。1県分の JSON は 3.4KB 以下。
- 結果（Lighthouse 13.6.0、スマホの既定の設定。上限のコンテンツのビルドを `wrangler dev` で配信。ハッシュなしのトップ）：

  - en：Performance 99、LCP 1.1秒、CLS 0、TBT 100ms、転送 267KB。
  - zh：Performance 100、LCP 1.2秒、CLS 0、TBT 80ms、転送 269KB。
  - `pnpm size`：ja 269.8KB・en 260.3KB・zh 262.2KB（gzip）。1県分の JSON は最大 3.4KB。
