## T5-01 執筆ルールとレビュー基準

- **種別**：docs
- **依存関係**：T1-07
- **目的**：生成エージェント・検証エージェント・レビュアーが、同じ基準で書き、同じ基準で確かめられるようにする。
- **参照仕様**：7.2、7.3、9.3、9.4

### 実装内容

- `content/guidelines/writing.md`：7.2・7.3・9.3 のルールを、良い例・悪い例（こども向け・おとな向け、3言語）を付けて書く。
- `content/guidelines/review-checklist.md`：9.4 の確認範囲（事実、出典、文字数、ふりがな、表現の適切さ、翻訳）をチェックリストにする。プレビューURLの開き方と、Suggested changes での直し方も書く。

### 完了条件

- markdownlint が通る。
- オーナーとレビュアーが内容を確認した。

### テスト条件

- 自動テストはない（文書のため）。
- 確認の方法：T5-04 の試行で実際に使い、分かりにくかった点を直す。

## T5-02 生成スキルと検証エージェント

- **種別**：feat
- **依存関係**：T5-01
- **目的**：9.2 の①〜④を、毎回同じ手順と品質で実行できるようにする。
- **参照仕様**：9.2、9.3、7.1〜7.3、D22

### 実装内容

- `.claude/skills/` に生成用のスキル：
  - ①おとな向けの日本語と出典の下書き（Web検索、出典ページを実際に開いて確認する）。
  - ③派生版（こども向けの日本語、英語、中国語）の生成。新しい事実を加えない。
- `.claude/agents/` に検証用のエージェント：②出典ページと内容の照合、④派生版とおとな向けの日本語の一致、文字数、ふりがな。
- 名前は既存のスキル・エージェントと重ならないようにする（例：`gotouchi-` を付ける。D22）。
- ふりがなの自動付与（7.2）：形態素解析のツールを選ぶ（推奨：pnpm で入るもの。Python など別の実行環境を増やさないため）。
- スキルの最後に `pnpm content:validate` を実行する。
- 生成用のスキル・検証用のエージェントは、`content/guidelines/writing.md`（T5-01）を読み込んで、同じ基準で書き・確かめる（文体・言語ごとの決まり・例）。基準を二重に書かず、この文書を参照する。

### 完了条件

- 1県分を①〜④で作り、`pnpm content:validate` を誤りなしで通るYAMLができる。

### テスト条件

- 確認の方法（LLMの出力なので、決まった入力・出力の自動テストにはしない）：
  - 検証エージェントに、わざと誤りを入れたYAMLを渡す（出典と違う数値、派生版で加えた事実、ふりがなの誤り、文字数の超過）。すべてが指摘されることを確かめ、結果をPRに書く。
  - 出典のURLが、実際に開いて確認できたものだけになっていることを確かめる（9.3）。

## T5-03 出典のリンク切れチェック

- **種別**：ci
- **依存関係**：T1-07
- **目的**：出典のリンク切れを、相手のサーバーに負担をかけずに見つけられるようにする。
- **参照仕様**：12.4、D15、R3

### 実装内容

- `scripts/check-links.ts`：
  - すべての `sources[].url` を集め、同じURLは1回だけ確かめる。
  - HTTPステータス、リダイレクト先、タイムアウトを記録する。
  - 同時に送るリクエスト数と、同じホストへの間隔に上限を設ける。
  - 結果を Markdown のレポートにする。対象の県を指定できる。
- `.github/workflows/link-check.yml`：`workflow_dispatch`（対象の県を入力で指定できる）。レポートを Artifact に保存する。
- リンク切れのときに Issue を自動で作るかを決める（推奨：作らない。四半期に1回の手動実行なので、レポートを見て人が作れば足りる）。→ **決定：作らない**。レポート（実行の概要・Artifact）と終了コード（リンク切れがあれば実行が失敗）だけにする。`issues: write` の権限も使わない。上限・分類・安全の方針は開発概要書 12.4。

### 完了条件

- `link-check` を手動で実行し、レポートが Artifact に保存される。

### テスト条件

- 単体（fetch を置き換える）：
  - 200、301 → 200、404、タイムアウトを、それぞれ正しく分類する。
  - 同じURLは1回だけ確かめる。
  - 同時のリクエスト数が上限を超えない。同じホストへの間隔が設定より短くならない。
  - 指定した県のURLだけを確かめる。
  - レポートの Markdown の形。

## T5-04 1県目（試行）

- **種別**：feat
- **依存関係**：T5-02、T0-06、T3-04
- **目的**：1県で制作の流れ（9.2 の①〜⑧）を最後まで通し、ほかの46県に広げる前に問題を直す。
- **参照仕様**：第9章

### 実装内容

- 1県を選ぶ（推奨：京都府。名物・名所の出典が見つけやすく、読みの難しい固有名詞も多いので、ルールの足りないところが見つかりやすい）。
- 9.2 の①〜⑧を実行する。レビュアーはプレビューURLで確認する（基準は `content/guidelines/review-checklist.md`）。
- ⑧：レビュアーの承認の後、オーナーが同じPRで `status` を `verified` から `reviewed` にするコミットを足してから merge する（レビュアーは `status` を直さない。T5-01 の判断）。この手順で困った点は、`review-checklist.md` に反映する。
- T5-01 の `writing.md`・`review-checklist.md` を実際に使い、分かりにくかった点を直す（T5-01 のテスト条件）。
- かかった時間と、見つかった問題を記録する。
- 問題を、スキル・エージェント・執筆ルール・レビュー基準に反映する（同じPRか、続くPRで）。
- `tests/data/content.test.ts` の「名物・名所は空で、行き方はない（未作成）」は、T1-08 で値を入れていないことを確かめるテストなので、外す（T1-08 で分かった）。県の YAML の先頭にある県庁の位置のコメント（D32）は残す。
- T5-02 の試行（京都府で①〜④。YAML はコミットしていない）で分かったこと。T5-04 で対処を決める：
  - **行き方の所要時間の出典**：JR東海の鉄道のサイト（`railway.jr-central.co.jp`）は、所要時間を検索フォームでしか出さず、WebFetch では確かめられなかった（`www.jr-central.co.jp` は証明書のエラー）。第三者のサイト（駅探、`jr-group.jp` は私設）は出典にできない。試行では `access` を書かなかった。対処の候補：オーナーが公式の検索で確かめて出典に書く、駅の時刻表の PDF など公式の固定のページを探す、出典なし（`sources: []`）で書く。
  - **回数の上限で `draft` に残った項目**：照合（②）と検証（④）は、どちらも2回目で「要確認」が1件ずつ残った（天橋立：2つの出典で地形の語が「砂州」と「砂嘴」で違う。西陣織：④の提案どおりに直した文で、英語・中国語との新しいずれ）。どちらも直し方は簡単だった。2回の上限が適切か、要確認だけなら3回目を許すかを決める。
  - **検証の結果のばらつき**：同じ文でも、エージェントを呼び直すと「出典の写しに近い」などの要確認が出たり出なかったりした。誤り（出典と違う数字・足した事実・読みの誤り）は毎回出た。要確認の扱い（どこまで直すか）を決める。
  - **かかった時間**：①〜④で約14分（出典の検索と WebFetch を含む。行き方なし）。
- **T5-04 の試行の結果（①〜④）**：
  - 名物は西陣織・宇治茶・京漬物、名所は清水寺・伏見稲荷大社・天橋立、行き方は東海道新幹線（東京駅 → 京都駅、134分）。照合（②）は1回目に要確認3件・誤り0件、2回目は指摘なし。検証（④）は1回目に要確認6件・誤り0件、2回目は指摘なし。3回目は要らなかった。
  - **行き方の所要時間の出典**：JR西日本の「JRおでかけネット」の列車ごとの時刻表（固定の URL）で、東京始発・毎日運転の「のぞみ25号」の東京発と京都着の時刻から決めた。書き方を `writing.md` 8 に足した。
  - **回数の上限**：2回のまま。2回目の後に要確認だけが残ったら、3回目を1回だけ許す。**要確認の扱い**：誤りは必ず直し、要確認は明らかによくなるものだけ直して、残りはレビュアーに回す。スキルに書いた。
  - **`web-fetch` の引用の制限**：サイトによっては原文の引用が1か所125字までで、残りは言い換えになる。頼み方をスキルに書いた。写しかどうかは、② の照合エージェントが自分でページを開いて比べる。
  - **公式のページの読みがな**：西陣織・清水寺・伏見稲荷大社の読みは、公式のページに書かれていなかった（清水寺は英語の表記 `Kiyomizu-dera` で「きよみずでら」と分かる）。宇治茶・京漬物は農林水産省のページに、天橋立は観光協会のページに読みがある。
  - **ふりがなの自動付与で直した語**：西軍（にしぐん → せいぐん）、覆下栽培（くつがえしも〜。文を書き直した）、11月（つき → がつ）、5,400本（ほん → ぽん）、日本三景（にっぽん → にほん）、すぐき漬（「漬」が辞書にない）。
  - **かかった時間**：①〜④で約13分（16:08〜16:21。出典の検索と `web-fetch`、② と ④ を2回ずつ）。

### 完了条件

- その県のすべての項目が `reviewed` で `main` に入っている。
- 見つかった問題を反映した。

### テスト条件

- CI（`pnpm content:validate`）と E2E が通る（E2E は開発中は `e2e.yml` を手動で実行する。D30。リリース後は U15 による）。
- レビュアーがプレビューURLでカードの表示を確かめ、PRを承認した（9.4）。
