## T1-02 読みがな・ローマ字の変換

- **種別**：feat
- **依存関係**：T0-02
- **目的**：市区町村のツールチップ（読みがな）と英語の表示（ローマ字）に使う文字列を、総務省のカナから機械的に作る。人の手で47県分を書かずに済むようにする。
- **参照仕様**：7.4、F-I18N-05、F-TIP-02、U12

### 実装内容

- 書き方を決める（開発計画 5章 U12 の推奨案：長音を書かない、市・区・町・村はハイフンで分ける）。結果を開発概要書 7.4 と第16章に書く。
- `geo/scripts/lib/kana.ts`：
  - カタカナ → ひらがな
  - ひらがな → ヘボン式ローマ字（先頭は大文字）
  - 接尾辞（市・区・町・村）を分ける
- 総務省のコード表のカナの形（T1-01 で確認。開発概要書 8.1）：
  - **半角カタカナ**で、濁点・半濁点が別の文字（`ﾎﾟ`）。NFKC で全角にしてからひらがなにする（`ﾎﾟ` → `ポ`）。
  - 使われている文字は `ｱ`〜`ﾝ`・小書きの `ｬｭｮｯ`・`ﾞﾟ` だけ。長音記号「ー」は使われていない。
  - 政令指定都市の区のカナは、市の名前から始まる（`ｻｯﾎﾟﾛｼﾁｭｳｵｳｸ` ＝ 札幌市中央区）。区だけの読みは、市のカナを先頭から取り除いて作る（T1-04）。
  - 団体コードは検査数字付きの6桁。上5桁が N03 の `N03_007` と一致する。

### 完了条件

- 開発概要書の U12 が決定になっている。

### テスト条件

- 単体（`geo/scripts/lib/kana.ts`）：
  - カタカナをひらがなにする。長音記号「ー」は残す。
  - し・ち・つ・ふ・じ → `shi`・`chi`・`tsu`・`fu`・`ji`。
  - 拗音：しゃ → `sha`、ちょ → `cho`。
  - 促音：さっぽろ → `Sapporo`、っち → `tch`。
  - 長音を書かない：とうきょう → `Tokyo`、おおさか → `Osaka`。ただし、いい・ええ は2文字のまま（いいだ → `Iida`）。
  - 接尾辞：さっぽろし → `Sapporo-shi`、ちゅうおうく → `Chuo-ku`。
  - ひらがな以外の文字が入っていたらエラーにする。

## T1-03 投影法の設定と沖縄の別枠

- **種別**：feat
- **依存関係**：T0-02
- **目的**：ビルド時（都道府県）と実行時（市区町村）で同じ投影法を使い、県境と市区町村の境界がずれないようにする。
- **参照仕様**：6.6 (1)、F-MAP-02、7.4

### 実装内容

- `src/features/map/projection.ts`：
  - d3-geo の投影法と、その設定値（中心、縮尺、位置）を定数として持つ。実行時にデータに合わせて計算し直さない（ビルド時と実行時で結果がずれないようにするため）。
  - 地図の `viewBox` の大きさ。
  - 沖縄県を左上の点線枠に移す変換（移動と縮尺）と、点線枠の位置。
  - 経度・緯度から画面の座標を返す関数（沖縄の変換を含む）。
- ビルド時の処理と実行時の処理は、どちらもこのモジュールだけを使う。

### 完了条件

- 投影法の種類と設定値を決めた理由を、モジュールのコメントか `geo/README.md` に書いた。

### テスト条件

- 単体（`src/features/map/projection.ts`）：
  - 東京都庁・北海道庁・鹿児島県庁の位置が `viewBox` の中に入る。
  - 沖縄県庁の位置は点線枠の中に移る（F-MAP-02）。
  - 沖縄県以外の位置は、沖縄の変換を受けない。
  - 同じ入力には、いつも同じ座標を返す。

## T1-04 地図データの変換スクリプト

- **種別**：feat
- **依存関係**：T1-01、T1-02、T1-03
- **目的**：N03 から、アプリが使う2種類の TopoJSON を、誰がいつ実行しても同じ結果になる手順で作る。
- **参照仕様**：第8章、7.4、F-MUNI-01、D16、D17

### 実装内容

- `geo/scripts/build-geo.ts`（mapshaper を使う。`pnpm geo:build` で手動で実行する）：
  1. N03 を読み込み、市区町村コードごとに形をまとめる（島などで1つの市区町村が複数の形に分かれているため）。
  2. 形を簡略化する。
  3. 市区町村ごとに `code`・`name.ja`・`kana`・`name.en`・`cityName`（政令指定都市の区だけ）を付ける。
  4. 県ごとに分けて `public/geo/muni/NN.topo.json` に書き出す。
  5. 市区町村の形を合わせて県の形を作り、県名ラベルの位置を付けて `geo/data/prefs.topo.json` に書き出す。形とラベルの位置は経緯度のまま入れる（投影と沖縄の別枠への移動は、描くときに T1-03 の `src/features/map/projection.ts` で行う。T2-04・T2-08）。
- 所属が決まっていない地域の扱い（T1-01 の結果）を決める。
- T1-01 で分かったこと（開発概要書 8.2）：
  - 全国の zip（`N03-20260101_GML.zip`、803MB。展開すると約2.6GB）に、市区町村の `N03-20260101` と、都道府県の形の `N03-20260101_prefecture` がある（それぞれ Shapefile・GeoJSON・GML）。Shapefile は UTF-8、JGD2011 の経緯度。県の形は、仕様（8.2）のとおり市区町村の形を合わせて作るので、`_prefecture` は使わない（使うと県境と市区町村の境界がずれるおそれがある）。
  - 形は125,130、コードは1,905。1つのコードが複数の形に分かれる（最大は小笠原村の4,812）。
  - 所属未定地：市区町村名が「所属未定地」、コードが `NN000`（県のコード）の形が7都県で141。どれも小さな島や埋立地。どの市区町村にも属さないので、市区町村として描くか（F-MUNI-01）、カードの市区町村の一覧に出すか、県の形に含めるかを決める。
  - 北方領土の6村（`01695`〜`01700`）が北海道に入っている。
  - カナとの照合はコードで行う。名前が違うのは高知県の檮原町（N03 は「檮」、総務省は「梼」）の1件。表示に使う名前をどちらにするかを決める。
- T1-02 で分かったこと（開発概要書 7.4.1、D33）：
  - `kana`・`name.en` は `geo/scripts/lib/kana.ts` の `katakanaToHiragana`・`municipalityRomaji` で作る。総務省のコード表の全件（シート1・シート2）が、エラーなく変換できることを確かめた。
  - **修正表を作る**（`geo/sources/` に、団体コードで引く2つの表）。機械的に作ると間違うものがあるため。下の件数は、T1-02 でコード表をスクラッチのスクリプトで調べた値で、リポジトリには残していない。T1-04 で全件の変換結果から数え直し、選び方と結果を `geo/README.md` に書く：
    - 読みの修正：拗音が大きい字で書かれている（少なくとも14件。庄内町 `ｼﾖｳﾅｲ`、中之条町、行田市、本庄市、羽生市、九十九里町、御宿町、鋸南町、竜王町、四條畷市、広陵町、総社市、新庄村、北谷町）。カナからは区別できない（「しよう」は し＋よう の読みもある）ので、`[きしちにひみりぎじびぴ][やゆよ]` を含む82件を見て選ぶ。
    - ローマ字の修正（語幹）：語の境目で長音の規則が母音を消す（勝浦 `Katsura`、松浦、瀬戸内 `Setochi`、豊岡 `Toyoka`、琴浦、豊浦、滝上 `Takinoe`、山ノ内、輪之内、勝央 `Sho`、曽於 `So`、東温、周防大島、豊後大野、山陽小野田 など）。全件の変換で母音が消えたもの（約660件）を見直して選ぶ。自治体の英語名（公式サイト）を目安にする。
  - 政令指定都市の区：コード表のシート2の区のカナは市のカナから始まる（`ｻｯﾎﾟﾛｼﾁｭｳｵｳｸ`）。区だけの読みを取り出してから `municipalityRomaji` に渡し、`name.en` を `Chuo-ku, Sapporo-shi` の形にする。`kana` は、`name.ja`（「札幌市中央区」）に合わせて市名を含む読み（`さっぽろしちゅうおうく`）にする案がある。T1-04 で決める。
  - コード表の Excel を読むとき、ふりがな（`<rPh>`）を除く。名前のセルにふりがなが入っているものがあり（色丹村・泊村・滝沢市・富谷市・白岡市・大網白里市・那珂川市の7件）、除かないと「色丹村シコタンムラ」になる。
- T1-03 で分かったこと（開発概要書 6.6 (1)）：
  - `prefs.topo.json` には沖縄の別枠の変換値を入れない（値は `src/features/map/projection.ts` だけに置く。7.4 を直した）。形と県名ラベルの位置は経緯度のまま入れ、投影は描くとき（T2-04・T2-08）に行う。
  - 小笠原村（父島・南鳥島・沖ノ鳥島）は投影すると `viewBox` の外に出る（U16。T2-04 で決める）。TopoJSON には含めておく。
- `geo/README.md`：手順、データの版、簡略化の度合い、所属が決まっていない地域の扱い、出典（8.3）。
- 変換した TopoJSON をコミットする。
- `pnpm lint` の Prettier のチェック（T0-01）は `geo/**/*.json` も対象にしている。生成した `geo/data/prefs.topo.json` は Prettier の整形に合わないので、`.prettierignore` に加えるか、チェックの対象から外す（`.prettierrc` は変えない）。

### 完了条件

- `public/geo/muni/` に47個、`geo/data/prefs.topo.json` に47県がある。
- 1県あたりの市区町村データが、圧縮後100KB以下（5.1）。超える県があれば、簡略化の度合いを調整する。
- `geo/README.md` の手順どおりに実行して、同じ出力になる。

### テスト条件

- 単体：
  - N03 の属性の1行から、市区町村の項目を作る関数。政令指定都市の区では `cityName` に市の名前が入り、それ以外では入らない。
  - 小さなフィクスチャ（2県・数個の市区町村の GeoJSON）で変換を通し、出力の TopoJSON の形（オブジェクトの名前、項目、県の数）が正しい。

## T1-06 ふりがなの記法のパーサー

- **種別**：feat
- **依存関係**：T0-02
- **目的**：ふりがなの記法を、ビルド時に安全に `<ruby>` へ変換できるようにする。記法の誤りをコンテンツの検証で見つけられるようにする。
- **参照仕様**：7.2、7.3、6.6 (2)

### 実装内容

- `src/lib/ruby.ts`：
  - `parseRuby(text)`：`{漢字|よみ}` を含む文字列を、文字の部分とルビの部分の配列にする。
  - `checkRuby(text)`：誤り（括弧の対応、空の読み、ひらがな以外の読み）と警告（ふりがなの付いていない漢字）の一覧を返す。
  - `plainText(text)`：読みを除いた文字列を返す（文字数の計算に使う。7.3）。
- `src/components/RubyText.tsx`：サーバーコンポーネント。`parseRuby` の結果を `<ruby>漢字<rt>よみ</rt></ruby>` として描く。`dangerouslySetInnerHTML` は使わない。

### 完了条件

- `src/lib/ruby.ts` のカバレッジが90%以上。

### テスト条件

- 単体（`src/lib/ruby.ts`）：
  - `{北海道|ほっかいどう}` → ルビの部分1つ。
  - 記法のない文字列 → 文字の部分1つ。記法と文字が混ざった文 → 順番どおりの配列。
  - 閉じ括弧がない、`|` がない → 誤り。
  - 読みが空 → 誤り。読みにカタカナ・漢字 → 誤り。長音記号「ー」は許す。
  - ふりがなの付いていない漢字 → 警告。
  - `plainText()` は読みを含まない（`{日本一|にほんいち}の` → `日本一の`）。
- コンポーネント（`RubyText`）：
  - `<ruby>北海道<rt>ほっかいどう</rt></ruby>` を出力する。
  - `<script>` を含む文字列は、タグではなく文字として表示される。

## T1-08 47県の基本情報

- **種別**：feat
- **依存関係**：T1-07、T1-01
- **目的**：名物・名所がなくても M2・M3 の画面を作れるように、全県の基本情報をそろえる。
- **参照仕様**：7.1、8.1、F-CARD-02、F-CARD-03、7.5

### 実装内容

- `content/prefectures/01-hokkaido.yaml`〜`47-okinawa.yaml`：`id`、`code`、`region`、`name`（3言語。日本語はふりがな付き、中国語は簡体字）、`capital.name`（3言語）、`capital.lat`・`capital.lon`（T1-01 で決めた出典の値）。
