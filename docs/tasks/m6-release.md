# M6 公開：タスクの定義

項目の意味と進め方は [development-plan.md](../development-plan.md) の第1章、進み具合は第3章にある。参照仕様の章番号は [開発概要書](../development-overview.md) のもの。

マイルストーンの完了条件：`https://maps.vivastack-dev.workers.dev/ja/` で公開されている。

---

## T6-01 実機での確認

- **種別**：手作業（オーナー）
- **依存関係**：T4-06、T5-05
- **目的**：CIでは確かめられない操作（ピンチ、下から出るパネル、オフライン、学校の端末）を、実際の端末で確かめる。
- **参照仕様**：5.3、D25

### 実装内容

- 前提：デプロイ（T0-06）が済んでいる。PWA・オフラインの確認は HTTPS の URL（本番かプレビュー）でしかできない（Service Worker が動かない LAN の `http://` の URL では確かめられない）。
- `docs/device-checklist.md`（T4-06）のとおりに、学校の端末（1つ前の iPadOS を含む）・スマホ・タブレットで確かめる。
- 結果（端末、OSの版、日付、問題）をチェックリストに書く。問題は修正のタスクにする。

### 完了条件

- チェックリストのすべての項目が問題なし、または修正済み。

### テスト条件

- 確認の方法：チェックリストの結果を記録したPR（docs）。

## T6-02 公開

- **種別**：chore
- **依存関係**：T6-01
- **目的**：本番に公開し、利用状況を見られるようにする。
- **参照仕様**：第13章、11.1、D21

### 実装内容

- Cloudflare Web Analytics に `maps.vivastack-dev.workers.dev` を手動挿入方式で登録する（11.1、D35）。本番用の CI ビルドで公開サイト識別子を渡し、言語別レイアウトに外部のモジュールスクリプトを出す。CSP は T4-01 で許可済みの配信元と送信先を使う。
- プライバシーポリシー（`/{lang}/privacy/`）の運営者 VivaStack と GitHub プロフィール、誤記・不具合の報告先である公開 GitHub Issues の案内を維持する（D47）。運営用メールアドレスの掲載はオーナー判断で見送る。
- コード・文書・県の解説文は現行の MIT ライセンスと著作権表示で公開し、地図データの出典と加工した旨の表示を残す。
- プライバシーポリシー（辞書の `privacy`。T4-05）は、Web Analytics を使う前提で書いてある（Cookie を使わない・集計する項目は Cloudflare の公式の文書のとおり）。スニペットを入れない、または集める項目が違うときは、公開の前に `privacy`（3言語）と `PRIVACY_REVISED_DATE` を直す。
- 初回公開では `CHANGELOG.md` に v1.0.0 を書き、`main` への merge を契機に本番へデプロイした。D50 以降は `main` に取り込んだコミットを指すタグで、GitHub Release を正式公開し、GitHub Actions でオーナーが本番デプロイを承認する（開発概要書 12.1）。
- 本番の URL に対する読み取り専用の E2E を、デプロイ成功後の独立した job で実行する（D49）。既存の全構成 E2E は手動実行を維持する。

### 完了条件

- `https://maps.vivastack-dev.workers.dev/ja/` で公開されている（M6 の完了条件）。
- Web Analytics で計測できている。
- 3言語のプライバシーポリシーから、運営者と公開の報告先を確認できる。

### テスト条件

- E2E（本番のURL）：
  - 3言語のページが表示される。
  - `/` が `/ja/` にリダイレクトされる（F-I18N-02）。
  - CSP などのヘッダーが付いている（5.5）。
  - 「準備中」の県がない（全項目が `reviewed`。4.11.4）。
  - Cloudflare Web Analytics のスクリプトが出力される（D21）。計測結果は本番デプロイ後にダッシュボードで確認する。
