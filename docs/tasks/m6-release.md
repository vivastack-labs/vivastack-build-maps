項目の意味と進め方は [development-plan.md](../development-plan.md) の第1章、進み具合は第3章にある。参照仕様の章番号は [開発概要書](../development-overview.md) のもの。

## T6-01 実機での確認

- **種別**：手作業（オーナー）
- **依存関係**：T4-06、T5-05
- **目的**：CIでは確かめられない操作（ピンチ、下から出るパネル、オフライン、学校の端末）を、実際の端末で確かめる。
- **参照仕様**：5.3、D25

### 実装内容

- 前提：デプロイ（T0-06）が済んでいる。PWA・オフラインの確認は HTTPS の URL（本番かプレビュー）でしかできない（Service Worker が動かない LAN の `http://` の URL では確かめられない）。
- `docs/device-checklist.md`（T4-06）のとおりに、学校の端末（1つ前の iPadOS を含む）・スマホ・タブレットで確かめる。
- 結果（端末、OSの版、日付、問題）をチェックリストに書く。問題は修正のタスクにする。

### 完了条件

- チェックリストのすべての項目が問題なし、または修正済み。

### テスト条件

- 確認の方法：チェックリストの結果を記録したPR（docs）。

## T6-02 公開

- **種別**：chore
- **依存関係**：T6-01
- **目的**：本番に公開し、利用状況を見られるようにする。
- **参照仕様**：第13章、11.1、D21

### 実装内容

- Cloudflare Web Analytics に `maps.vivastack-dev.workers.dev` を登録する（11.1）。workers.dev では自動設定が使えない見込みなので、ダッシュボードで確かめ、使えなければ計測用のJSスニペット（トークン入り）をHTMLに埋め込む（D35。CSP は T4-01 で Web Analytics のドメインを許可済み。スニペットは外部の `src` なので、ハッシュは要らない。インラインで書くと、T4-01 の検査でビルドが止まる。`next/script` の `beforeInteractive` は使わない〔`(self.__next_s=…)` のインラインが出てビルドが止まる〕。レイアウトにふつうの `<script defer src=… data-cf-beacon=…>` を書く）。結果を開発概要書 11.1 に書く。
- プライバシーポリシー（`/{lang}/privacy/`）には、運営者の VivaStack と GitHub プロフィール、誤記・不具合の報告先としてプロジェクトの公開 GitHub Issues を載せる（D47）。個人情報や著作権に関する連絡を受ける運営用メールアドレスを決め、3言語に追記して `PRIVACY_REVISED_DATE`（改定日）を更新する。
- コード・文書・県の解説文は現行の MIT ライセンスで公開し、地図データの出典と加工した旨の表示を残す。`LICENSE` の著作権表示の名義は、権利者を確認したうえで変更の要否を決める。
- プライバシーポリシー（辞書の `privacy`。T4-05）は、Web Analytics を使う前提で書いてある（Cookie を使わない・集計する項目は Cloudflare の公式の文書のとおり）。スニペットを入れない、または集める項目が違うときは、公開の前に `privacy`（3言語）と `PRIVACY_REVISED_DATE` を直す。
- `CHANGELOG.md` に v1.0.0 を書き、`main` に merge して本番にデプロイする。
- 本番のURLに対する確認用の E2E（読むだけの操作）を用意し、デプロイの後に実行する。

### 完了条件

- `https://maps.vivastack-dev.workers.dev/ja/` で公開されている（M6 の完了条件）。
- Web Analytics で計測できている。
- 3言語のプライバシーポリシーに運営者、公開の報告先、非公開で連絡できる運営用メールアドレスが載っている。

### テスト条件

- E2E（本番のURL）：
  - 3言語のページが表示される。
  - `/` が `/ja/` にリダイレクトされる（F-I18N-02）。
  - CSP などのヘッダーが付いている（5.5）。
  - 「準備中」の県がない（全項目が `reviewed`。4.11.4）。
