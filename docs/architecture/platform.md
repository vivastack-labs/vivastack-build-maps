# アーキテクチャ：CSP・PWA・アクセシビリティ・対応環境

エージェント向けの実装メモ（`AGENTS.md` の「アーキテクチャ」から分けた）。この範囲のコード・テストを変える前に読み、変えたら更新する。「上の〜」「下の〜」で指す節は、同じフォルダのほかのファイルにあることがある。

- CSP（T4-01。5.5、6.6 (4)、D39、R9）：`scripts/postbuild.ts` の `writePageCsp(dist)` が、`dist/` のすべての HTML に、そのページのインラインスクリプト（`src` のない `<script>`）の SHA-256 を入れた `<meta http-equiv="Content-Security-Policy">` を `<meta charset>` の直後に書く（`_headers` は1行 2,000 字までで、ハッシュが入らないため）。`public/_headers` の `/*` には `frame-ancestors 'none'; object-src 'none'; base-uri 'self'` だけ（`<meta>` では効かないもの）。`style-src 'self'`・`script-src 'self'` ＋ハッシュ ＋ `https://static.cloudflareinsights.com`、`'unsafe-inline'`・`'strict-dynamic'` は使わない。
  - **インラインスクリプトを足すとき**：HTML に出れば、ハッシュは自動で入る。ただし知っている形（全体に一致するもの：`KNOWN_EXACT_INLINE_SCRIPTS`〔`MODE_INIT_SCRIPT` と `(self.__next_f=…).push([0])`〕、`self.__next_f.push(…)` の RSC のデータ、Turbopack の JSON）に合わないと、`postbuild.ts` がビルドを止める（紛れ込んだスクリプトを自動で許可しないため）。`dangerouslySetInnerHTML` は `MODE_INIT_SCRIPT` だけ。`MODE_INIT_SCRIPT` は定数を変えるだけなら通る（完全一致の相手が同じ定数）。2つ目のスクリプトは `KNOWN_EXACT_INLINE_SCRIPTS` に足す。`next/script` の `beforeInteractive` は `(self.__next_s=…)` のインラインが出てビルドが止まる（T6 の Web Analytics には使わない）。`initScript.ts` の相対 import に `.ts` を付けるのは、`postbuild.ts` が Node.js で読むため。
  - **HTML の形の検査**：`postbuild.ts` は、`<style>` 要素・`style` 属性・`<meta charset>` より前の `<script>`・`<link>`、JavaScript・JSON 以外の type の `<script>`（importmap・speculationrules）があればビルドを止める。CSP を書けなかったときは `dist/` を消す。**`pnpm dev` には CSP がかからない**（postbuild が動かないため）。CSP の確認は `pnpm build` ＋ `wrangler dev` か E2E で行う。
  - **サーバーの HTML に `style` 属性を出さない**（`style-src 'self'` は HTML の style 属性を止める）。見た目は Tailwind のクラス（任意値 `[stroke-width:calc(0.8px/var(--zoom-k,1))]`・`aspect-[1000/1130]` など。クラス名は組み立てずに全体を書く）で書く。JavaScript から `element.style.setProperty` など（CSSOM）で書く値と、React がクライアントで描く `style` は止まらないので、使ってよい。`<style>` 要素・`onclick=` などのインラインのイベント属性も使わない。E2E で `page.addStyleTag` は使えない（CSSOM で書く）。
  - E2E は `tests/e2e/csp.spec.ts`（3言語の主な操作・404 の間に CSP 違反 0件、CSP の `<meta>` の位置、`_headers` の `frame-ancestors`、知らないインラインスクリプトが止まること）。Web Analytics のスニペット（T6）は外部の `src` なので、ハッシュは要らない。
- PWA（T4-02。5.4、U3・U13、D40・D41、4.11.5）：
  - manifest：`app/[lang]/app.webmanifest/route.ts`（`force-static`。カードの JSON と同じ形）が、`src/features/pwa/manifest.ts` の `webManifest(lang)` から `/ja/app.webmanifest` などを出す（名前は辞書の `siteName`・`pwa.shortName`〔ふりがなの記法は除く〕。`id`・`start_url` は `/{lang}/`、`scope` は `/`）。`generateMetadata` の `manifest`・`icons` でリンクする。アイコン（仮）は `public/icons/`。`scripts/make-icons.ts`（日本の形を `prefs.topo.json` から描く。Playwright の chromium で PNG にする）で作り直せる。名前を `manifest.webmanifest` にしないのは、Next.js のメタデータのファイルと紛れないため。
  - `sw.js`：`scripts/service-worker.ts` の `writeServiceWorker(dist)`（`workbox-build` の `generateSW`。`inlineWorkboxRuntime` で1ファイル）が、`scripts/postbuild.ts` の最後（`assembleDist` → `writePageCsp` → `writeServiceWorker`。`assembleDistWithCsp` は async）で `dist/sw.js` を作る。失敗したら `dist/` を消す。プリキャッシュは `PRECACHE_PATTERNS`（3言語×3ページ〔`PAGES`。トップ・`about/`・`privacy/`。T4-05〕の `index.html`・`app.webmanifest`・`_next/static/` の JS・CSS・`icons/`。HTML の版は CSP を書いた後の内容のハッシュ）で、パターンに合うファイルがない・大きさの上限を超えて外れたものがあると例外。ページを足すときは、`PAGES` に足すと自動でここに入る（足さないものは、オフラインでは開けない）。市区町村（`/geo/muni/NN.topo.json`）・カード（`/cards/{lang}/NN.json`）は、一度読んだものだけを NetworkFirst（キャッシュ名 `maps-muni`・`maps-cards`。200 だけ）。`skipWaiting`・`clientsClaim`。
  - 登録：`ServiceWorkerRegistration`（クライアント。`app/[lang]/layout.tsx` の `<body>` の最後。DOM を出さない）が、本番のビルドだけ、ページの読み込みの後に `/sw.js` を `scope: '/'` で登録する（`pnpm dev` では登録しない。失敗は握りつぶす）。外部のファイルなので、CSP のハッシュは増えない。`public/_headers` の `/sw.js` は `no-cache`。
  - **E2E は Service Worker を使わない**：3つの Playwright の設定（`playwright.config.ts`・`playwright.preview.config.ts`・`playwright.screenshots.config.ts`）の `use` に `serviceWorkers: 'block'`（`page.route` で失敗・遅延を作るテストが、Service Worker に横取りされないため）。`tests/e2e/pwa.spec.ts` だけ `serviceWorkers: 'allow'`（Chromium のデスクトップだけ。登録・オフラインの再読み込み・オフラインの市区町村・manifest・CSP 違反なし。キャッシュに入るのを `caches` で待ってから `context.setOffline(true)` にする）。
  - **手元の `wrangler dev`（8787番）や本番のビルドを開いたブラウザには Service Worker が残る**：古い HTML・JS が出たら、2回読み込む（1回目で新しい `sw.js` を取って有効になり、2回目で新しい内容になる）。DevTools の Application で Unregister してもよい。
- アクセシビリティの検査（T4-03。5.2、WCAG 2.2 AA）：
  - axe の E2E は `tests/e2e/a11y.spec.ts`（`@axe-core/playwright`。タグ `wcag2a`・`wcag2aa`・`wcag21a`・`wcag21aa`・`wcag22aa`。除外はしない）。3言語 × 2モード（`MODE_STORAGE_KEY` を `addInitScript` で入れる）× ライト・ダーク（`emulateMedia`）で、PC は chromium だけ（最初の表示・固定中〔`#pref-01` から復元〕・最大化中）、パネルは pixel だけ（閉じた最初の表示・`peek`・`full`）。計72件。`openPage` が、モード（`data-mode`）と配色が実際に切り替わったことを確かめる。新しい画面の状態や部品を足したら、ここに状態を足す。`[data-card-ready]`・`[data-muni-list]` などは表示されていないことがあるので、`waitFor({ state: 'attached' })` で待つ。
  - 色は `tests/unit/styles/theme-contrast.test.ts` が、`app/globals.css` の `@theme`（ライト）と `@media (prefers-color-scheme: dark)`（ダーク）の変数から `src/lib/contrast.ts` の `contrastRatio` で計算する（axe は SVG の中の文字の色を判断できない）。色の読み取りは `src/lib/cssTheme.ts` の `parseThemes`（hex 以外の値〔`var()`・`oklch()`・8桁の hex など〕・ダークの `@media` が2つ以上は例外）。自動で確かめるのは、テストに書いた組み合わせの値を変えたときだけなので、**新しい色の変数や、新しい文字と塗りの組み合わせ（文字は 4.5:1、線・図形は 3:1）は、このテストに組み合わせを足す**。
  - 固定中の県の県名ラベル：暗い文字（`--color-map-selected-label`）に、塗り（`--color-map-selected`）と同じ色の縁取りを付ける（`JapanMap` の `PINNED_LABEL_CLASS`。文字の下に描く `paint-order`、太さ `calc(3px/var(--zoom-k,1))`）。暗い文字が県の形からはみ出して海・地方の塗りの上に出ても読めるようにするため（ダークの塗り `#d97706` と白に近い文字は 3.04:1 で足りない）。そのため、固定中のラベルと海・地方・準備中の地の比はテストしない。`applyPrefState` がラベル（`[data-pref-label]`）にも `data-state="pinned"` を書く。
  - 県境の線（`--color-map-border`）・市区町村の境の線（`--color-muni-border`）は、隣り合う塗りと 3:1 以上（ダークの県境は `#f8fafc`。固定中の塗りが中間の明るさのため）。
  - 見える文字がある要素に、見える文字と違う `aria-label` を付けない（WCAG 2.5.3。ja の「全体」ボタンで違反になった）。見える文字が記号のもの（「＋」「−」）は `aria-label` を付けてよい。
  - 404画面は `a11y.spec.ts` でライト・ダークの axe 検査を行う。`workers.spec.ts` では HTTP 404・日本語の文書・`noindex` と、キーボードや JavaScript 無効時の復帰を確かめる。
- 対応環境の確認（T4-06。5.3、D25）：Playwright のプロジェクトは9つ（`playwright.config.ts` のコメントに端末と幅の対応）。PC：`chromium`・`firefox`・`webkit`（1280px）・`chromebook`（Chromium、1366×768）。タッチ：`iphone`（402px）・`pixel`（360px）・`ipad-portrait`（768px）・`ipad-landscape`（1194px）・`android-tablet`（Galaxy Tab S9 の横、1024px）。
  - **PC だけ・タッチだけのテストは、`test.skip(hasTouch…)` ではなくタグで書く**：`test('…', { tag: '@pc' }, …)`・`test.describe('…', { tag: '@pc' }, …)`（マウス・キーボード・`setViewportSize` を使うもの）、`@touch`（タップを使うもの）。`pcProject`・`touchProject` が、PC のプロジェクトでは `@touch` を、タッチのプロジェクトでは `@pc` を `grepInvert` で除く（`hasTouch` で決まる）。「代表の1つで確かめる」ものは `test.skip(testInfo.project.name !== 'chromium', …)`（`browserName` では書かない。chromebook も Chromium で、同じ検査が2回動くため）。プロジェクトを足すときは、`e2e.yml` の `project` の選択肢と `install` の `case` も合わせる（`tests/unit/config/playwright-projects.test.ts` が選択肢・タグ・`test.skip` の書き方を止める）。
  - **テストの引数で `hasTouch`・`isMobile`・`browserName` を受け取らない**（`tests/unit/config/playwright-projects.test.ts` が `tests/e2e/` の下すべてで止める）。受け取ってよいのは、操作の一部だけを分けるファイルで、`FIXTURE_EXCEPTIONS`（ファイルと理由の一覧。今は `csp.spec.ts` のホバーだけ）に足す。
  - 横スクロールの検査は `tests/e2e/layout.spec.ts`（3言語 × `PAGES` ＋ 404 を、端末の幅と、PC の幅360pxの指定で）。内容を広げた状態は、英語の北海道のカード・市区町村の一覧の JSON を `page.route` で長い URL・長い1語の名前に書き換えて開き、幅 360px・800px・1024px で、文書とカードの領域（`[data-area="card"]`。768px 未満は fixed のパネル、1024px 以上も `overflow-y-auto` の箱で、はみ出しは中でスクロールになり文書の検査では見えない）の両方を確かめる。ページを足すと自動で対象になる。
  - CI で確かめられないもの（ピンチ・Apple Pencil・ホーム画面への追加・オフライン・1つ前の iPadOS など）は `docs/device-checklist.md`。公開前（T6-01）に確かめ、結果を表に書く。
- 本番のアクセス解析（T6-02、D21・D35）：`app/[lang]/layout.tsx` は、本番の静的ビルドで公開サイト識別子 `CLOUDFLARE_WEB_ANALYTICS_SITE_ID` が渡された場合に、公式の外部モジュールスクリプトを1つ出す。`deploy.yml` は GitHub Actions のリポジトリ変数から識別子を渡す。計測用スクリプトの読み込みは `tests/e2e/csp.spec.ts`、プレビューへの混入防止は `tests/e2e-preview/analytics.spec.ts` で確かめる。
- 本番デプロイ（D50）：`deploy.yml` は GitHub Release の `published` イベントで起動する。正式版のタグ書式と `main` の履歴をビルド前に検証し、3 job はイベントのコミット SHA を使う。`production` Environment が許可する `v*` タグはルールセットで保護し、デプロイの前にオーナーの承認を必須にする。
- デプロイ後の読み取り検査（T6-02、D49）：`playwright.production.config.ts` と `tests/e2e-production/release.spec.ts` は、配信済みの HTML とヘッダーを JavaScript 無効の Chromium で確認する。`deploy.yml` の `smoke` job はデプロイ成功後に実行する。既存の全構成 E2E は手動の `e2e.yml` で実行する。
