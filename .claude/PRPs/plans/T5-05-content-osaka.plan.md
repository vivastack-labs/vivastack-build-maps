# T5-05 残りの46県：1県目（大阪府）の実装計画

- タスクの定義：`docs/tasks/m5-content.md` の T5-05
- ブランチ：`feat/T5-05-content-osaka`
- PR のタイトル：`feat: add content for Osaka (T5-05)`
- 参照仕様：開発概要書 第9章（9.2 の①〜⑧、9.3、9.4）、`content/guidelines/writing.md`・`review-checklist.md`、スキル `gotouchi-content`

T5-05 は県ごとに PR をくり返す。この計画は大阪府の PR の分で、ほかの県の PR は、この計画の「進め方」を写して使う（県ごとの計画ファイルは作らず、PR の本文に判断を書く）。

## 目的

大阪府の名物3・名所3・行き方を `reviewed` にして `main` に入れる。あわせて、京都府（T5-04）で確かめられなかった**レビュアーの承認（Approve）と Suggested changes の流れ**を、`maps-reviewers` のレビュアーで確かめる。

## 着手時に分かっていること

- `content/prefectures/27-osaka.yaml` は基本情報だけ（`specialties: []`・`spots: []`・`access` なし）。
- 行き方を書かないと、本番では「準備中」のまま（`isComplete`）。
- Team `maps-reviewers` のメンバーは `inspireme` の1人。PR の作者（オーナー）とは別のアカウントなので、GitHub の承認が出せる。
- 前回のテスト `tests/data/content.test.ts` の「未作成」は T5-04 で外してあるので、テストの変更はない。
- この PR で、`CHANGELOG.md` は書かない（M5 の最後の県の PR で書く）。

## 進め方

1. **①〜④（スキル `gotouchi-content`、引数 `27`）**：メインのセッションで動かす（②・④の検証エージェントと `web-fetch` を呼ぶため）。始めと終わりの時刻、手順ごとの時間、指摘の件数を記録する。
2. **検査**：`pnpm content:validate`・`pnpm lint`・`pnpm typecheck`・`pnpm test`・`pnpm build`・`pnpm build:preview`。
3. **⑤ PR**：`status: verified` で出す。本文に、項目ごとの出典・要確認の読み・行き方の時間の内訳・かかった時間を書く。
4. **⑥**：オーナーが `preview` を承認 → プレビュー URL（`https://pr-<番号>-maps.vivastack-dev.workers.dev/ja/`）で、3言語・2モードのカードを確かめる。
5. **⑦**：`inspireme` がレビューする。Suggested changes の画面の名前を確かめ、`review-checklist.md` 5. を実際の画面に合わせて直す。提案の取り込みと Re-request review の流れも確かめる。
6. **⑧**：レビュアーが承認した後、オーナーの依頼で `status` を `reviewed` にするコミットを足し、merge する。merge の後、本番で大阪府のカードが出ることを確かめる。
7. E2E は `e2e.yml` を手動で実行せず、手元で `pnpm test:e2e`（フィクスチャを使うので、内容には影響されない。データの変更で壊れていないことの確認）。
