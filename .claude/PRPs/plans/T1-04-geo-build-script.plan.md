## 判断が必要な点（すべて推奨案で承認された）

### 1. 簡略化の度合い

- **採用**：市区町村は `interval=100`（100m）・`quantization=50000`。都道府県は `interval=1000`（1km）・`quantization=100000`。どちらも `keep-shapes`（小さな島を消さない）。
- 理由：市区町村は最大の北海道で 84KB と基準に余裕があり、最大化した画面で角ばりが目立たない。都道府県は HTML に SVG として埋め込むので、最初の読み込み（5.1）に効く。1km で約39KB。値は `GEO_BUILD_SETTINGS` にあり、T2-04 で測って変えられる。
- 影響：最大化した県と周りの県の境界が最大で約1kmずれる。T2-08 の定義に書き足した。

### 2. 所属未定地（7都県・141の形）の扱い

- **採用**：市区町村のファイルには入れない。県の形には含める（D34）。
- 理由：市区町村ではないので、名前・読み・ローマ字を作らずに済む。市区町村の数が総務省のコード表と一致する。最大化したときは県の形を下に描くので、穴にはならない。

### 3. 政令指定都市の区の `kana`

- **採用**：市名を含む読み（`さっぽろしちゅうおうく`）。`name.en` は区だけの読みから `Chuo-ku, Sapporo-shi`。
- 理由：`name.ja`（「札幌市中央区」）と、ツールチップの「市名＋区名」（F-TIP-02）にそろう。

### 4. 檮原町の名前（N03「檮」、総務省「梼」）

- **採用**：名前はすべて N03 のものを使い、総務省のコード表はカナにだけ使う（照合はコード）。レビューの後、名前も比べるようにし、檮原町だけを字体の違いとして通す。
- 理由：形と名前の出典が1つになる。「檮」は今の端末のフォントで表示できる。

### 5. 修正表の作り方

- **採用**：`geo/sources/` に CSV を2つ置く。列に「直す前の値」を持ち、今の変換結果と一致しなければ止める。表のコードが地図にないときも止める。候補は全件の変換から機械的に出し、Claude が漢字の区切りと自治体の英語名を目安に選んだ（選び方と一覧は `geo/README.md`）。
- 理由：年1回の更新でカナが変わったとき、古い修正が黙って当たり続けない。CSV は GitHub で表として読める。

### 6. 総務省の xlsx の読み方

- **採用**：コミットせず、`geo/downloads/` の xlsx を毎回読む。fflate で展開し、XML は正規表現で必要な要素だけを取り出す。
- 理由：入力は2つとも「ダウンロードしたもの」で、手順が同じになる。xlsx を読むライブラリは大きく、使うのは3列だけ。

### 7. 出力の属性

- **採用**：市区町村は `{ code, name: { ja, en }, kana, cityName? }`。都道府県は `{ code: "01", label: [経度, 緯度] }`（小数4桁）。オブジェクト名は `municipalities`・`prefectures`。市区町村にはラベルの位置を入れない。
- 理由：7.4 の項目のとおり。市区町村のラベル（F-MUNI-02）は T2-08 で決める。

### 8. 依存の追加

- **採用**：`mapshaper@0.7.101`・`fflate@0.8.3` を devDependencies に固定の版で入れ、`better-sqlite3`・`msgpackr-extract` のインストールスクリプトは `allowBuilds` で止める。
- 理由：手動で実行する変換にだけ使い、配信物には入らない。
