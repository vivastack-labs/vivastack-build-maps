## 判断が必要な点

### 1. 簡略化の度合い

- **推奨**：市区町村は `interval=100`（100m）・`quantization=50000`。都道府県は `interval=1000`（1km）・`quantization=100000`（配信しないので細かくてよい）。どちらも `keep-shapes`（小さな島を消さない）。
- 理由：市区町村は、最大の北海道で 81.5KB と100KB に余裕があり、最大化した画面で角ばりが目立たない。都道府県は HTML に SVG として埋め込むので、最初の読み込み 300KB（5.1。JS・カードの内容を含む）の中に収める必要があり、1km で 35KB。全国の表示（1px ≒ 2km）では 1km の簡略化は見分けられない。値は定数にしておき、T2-04 で HTML 全体を測って変えられる。
- 代わりの案：都道府県も 500m（68KB。地図を拡大したときの海岸線がなめらか）。
- **影響**：都道府県と市区町村で簡略化の度合いが違うので、最大化した県（市区町村の形で描く）と、周りの薄く描く県（都道府県の形）の境界が、最大で約1km ずれる（神奈川県を900pxで出すと数px）。どちらも同じ元の形から作るので、ずれは簡略化の幅の中に収まる。8.2 の「県境と市区町村の境界が必ず一致する」は、同じ1枚の中（都道府県どうし、市区町村どうし）の話になる。描き方の工夫（最大化した県を上に重ねる など）は T2-08 に書き足す。

### 2. 所属未定地（7都県・141の形）の扱い

- **推奨**：市区町村のファイルには入れない。県の形には含める。
- 理由：市区町村ではないので、名前・読み・ローマ字を作らずに済む（総務省のカナもない）。市区町村の数が総務省のコード表と一致する（T1-05 のテスト）。最大化したときは県の形を下に描く（4.11.5 の「県の形だけを先に表示」と同じ）ので、穴にはならない。
- 代わりの案：「所属未定地（しょぞくみていち）」という項目として市区町村のファイルに入れる（ツールチップが出るが、名前と英語を自分で作ることになり、カードの市区町村の一覧から除く処理も要る）。

### 3. 政令指定都市の区の `kana`

- **推奨**：市名を含む読み（`さっぽろしちゅうおうく`）。総務省のカナをそのまま使う。`name.en` は区だけの読みから `Chuo-ku, Sapporo-shi`（D33 のとおり）。
- 理由：`name.ja`（「札幌市中央区」）と、ツールチップの「市名＋区名」（F-TIP-02）にそろう。

### 4. 檮原町の名前（N03「檮」、総務省「梼」）

- **推奨**：名前はすべて N03 のものを使い、総務省のコード表はカナにだけ使う（照合はコード）。
- 理由：形と名前の出典が1つになる。「檮」は今の端末のフォントで表示できる（JIS X 0213）。

### 5. 修正表の作り方

- **推奨**：`geo/sources/` に CSV を2つ置く。列に「直す前の値」（`before`）を持ち、変換のときに今の結果と一致しなければエラーにする。候補は全件の変換から機械的に出し（読み：`[きしちにひみりぎじびぴ][やゆよ]` を含む約82件、ローマ字：長音の規則で母音が消えた約660件）、私（Claude）が漢字の区切りと自治体の英語名を目安に選ぶ。選んだ一覧は PR で見てもらう。
- 理由：「直す前」を持つと、年1回の更新でカナが直ったり変わったりしたとき、古い修正が黙って当たり続けない。CSV は GitHub で表として読める。660件は数が多いので、選ぶ規則（例：漢字の読みの境目で母音が続くなら消さない。勝浦 かつ｜うら → `Katsuura`、大阪 おお（1字）→ `Osaka`）を `geo/README.md` に書き、例外を表で見てもらう。
- 代わりの案：JSON（Prettier で整形される。差分は読みにくい）。

### 6. 総務省の xlsx の読み方

- **推奨**：コミットせず、`geo/downloads/` の xlsx を毎回読む（N03 と同じ扱い）。読むのは fflate（依存なし、mapshaper も使っている）で展開し、XML は正規表現で必要な要素だけを取り出す。
- 理由：入力は2つとも「ダウンロードしたもの」で、手順が同じになる。xlsx を読むライブラリ（SheetJS・exceljs）は大きく、使うのは2列だけ。
- 代わりの案：カナの表を CSV にしてコミットする（変換の入力が見えるが、総務省の表を写したファイルが増える）。

### 7. 出力の属性

- **推奨**：市区町村は `{ code, name: { ja, en }, kana, cityName? }`（7.4 のとおり）。都道府県は `{ code: "01", label: [経度, 緯度] }`（小数4桁）。オブジェクト名は `municipalities`・`prefectures`。市区町村にはラベルの位置を入れない。
- 理由：7.4 の項目のとおり。市区町村のラベル（F-MUNI-02）は、間引きと一緒に T2-08 で決める（実行時に d3 で計算するか、ここに足すか）。足すときは定数を変えて作り直すだけ。
- 代わりの案：市区町村にも `label` を入れておく（約1,900件 × 20バイト。T2-08 で使わなければ無駄になる）。

### 8. 依存の追加

- **推奨**：`mapshaper@0.7.101`・`fflate@0.8.3` を devDependencies に固定の版で入れる。`better-sqlite3`・`msgpackr-extract` のインストールスクリプトは `allowBuilds` で止める。
- 理由：手動で実行する変換にだけ使い、配信物には入らない。インストールスクリプトのある2つは、使わない形式（GeoPackage・msgpack）のためのもの。0.7.101 は公開から2週間たっている。
