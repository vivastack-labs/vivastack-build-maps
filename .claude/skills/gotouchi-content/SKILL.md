# gotouchi-content：1県分のコンテンツを①〜④で作る

開発概要書 9.2 の①〜④を、毎回同じ手順と品質で行う。**事実は、おとな向けの日本語で確定させ、ほかの版はそこから作る**。
このスキルは `content/prefectures/<code>-<id>.yaml` の1ファイルを書き換える。`reviewed` にするのは、レビューの承認の後（オーナー）なので、このスキルは `verified` までにする。

## はじめに

1. **`content/guidelines/writing.md` を全部読む。** 文体・言語ごとの決まり・文字数・ふりがな・YAML の書き方・避けることは、すべてそこにある。このファイルには写さない（ルールを直したときに食い違うため）。`review-checklist.md` は、レビュアーが見る基準なので、書き終えてから、見落としがないかの確認に使う。
2. 県を決める。引数が県コード（`26`）なら `content/prefectures/26-*.yaml`、id（`kyoto`）なら `content/prefectures/*-kyoto.yaml` を開く。県の基本情報（`id`・`code`・`name`・`capital`）はそのまま残す。
3. 始めた時刻を控える（`date`）。報告に、かかった時間を書く（T5-04 の記録に使う）。
4. 手順の指定（③④だけ、など）や項目の指定があれば、その部分だけを行う。指定のない部分の文は変えない。

YAML の形（項目の名前・入れ子）は、`tests/fixtures/content/01-hokkaido.yaml` が見本になる（**中身はテスト用のダミーで、事実ではない。写さない**）。スキーマは `content/schema/prefecture.schema.json`。

## Web のページを開く

出典のページは、WebFetch で**実際に開いて**読む。WebFetch が使えない環境では、`web-fetch` エージェントに URL を渡して頼む（`web-fetch` はこの環境が用意するエージェントで、このリポジトリにはない）。

- ページを頼むときは、**該当する段落を原文のまま返す**よう頼む。要約では、出典の文の写しになっていないかを判断できないため。
- 開けなかったページは、出典にしない（9.3）。検索の結果の一覧や、題名だけでは、「開いた」ことにならない。
- WebFetch も `web-fetch` も使えないときは、①・② を止めて、そのことを報告する（開けない出典を、もっともらしく書かない。出典にしない）。

## ① 下書き：おとな向けの日本語と出典

1. 県の名物3・名所3・行き方（東京から）を選ぶ。選ぶ基準：県を代表する（観光協会・自治体の公式の紹介にある）、出典が実際に開いて確かめられる、特定の店・商品・宿の宣伝にならない、季節が限られるものは時期を書ける（writing.md 9）。名物と名所で似たものを重ねない。
2. 項目ごとに、Web で出典を探し、**実際に開いて読む**。優先順位は writing.md 3（公式 → 公的機関の一覧 → それ以外）。
3. 読んだ内容を、自分の言葉で要約して、おとな向けの日本語を書く（`description.ja.adult`）。名前（`name`）・`emoji`・`id`（英小文字と `-` だけ）・`sources`（`title` は開いたページの題名のまま、`accessed` は開いた日）も書く。行き方は `mode`・`route`・`durationMin`（交通機関の公式の情報から。writing.md 8）。
4. 日本語の文には、`pnpm content:furigana` でふりがなを付ける（付いていない漢字にだけ付く。すでにある `{…|…}` は変えない）。

   ```bash
   source ~/.nvm/nvm.sh && nvm use >/dev/null
   pnpm content:furigana "涼しい気候を生かして、秋に収穫されます。"
   ```

   - 標準出力が、ふりがなを付けた文。YAML には、これを writing.md 11 の書き方で貼る。ファイルは書き換えない。
   - 標準エラーの「要確認」は、**読みが怪しい語**（固有名詞・辞書にない語・送り仮名で区切れなかった語に加えて、漢字の続きが2つ以上の語に分かれた複合語と、数字の後の漢字）。文には、分かれたまま、または辞書の読みのまま付いている（要確認は一覧に出るだけで、文は変わらない）。例：紋織物が `{紋織|もんおり}{物|ぶつ}`（正しくは「もんおりもの」）、11月が `11{月|つき}`（正しくは「がつ」）になる。分かれても正しいこともある（総本宮の `{総|そう}{本宮|ほんぐう}`）。語ごとに、公式の表記（自治体・観光協会・交通機関のサイト。出典のページ）で読みを確かめて、直す。辞書にない語は、ふりがなが付いていないので、読みを調べて手で付ける。
   - 読みの確かめは、出典のページに読みが書かれていなければ、公式サイトの別のページ（アクセス・施設の案内など）を探す。それでも確かめられなければ、報告の「要確認の読み」に残す。
5. 項目の `status` は `draft`。

## ② 照合

`gotouchi-source-checker` エージェントに、YAML のパスと対象の項目を渡す。報告の「指摘」を直す。

- 事実が出典と違う → おとな向けの日本語を、出典に合わせて直す（ふりがなも付け直す）。
- 出典の文の写し → 自分の言葉で書き直す。
- 出典を確かめられない（開けない・内容が違う）→ その出典を外す。ほかに確かめられる出典を探してもよい。確かめられる出典がなければ `sources: []`（writing.md 3。画面には「出典なし」と出る）。
- 直したら、**もう一度**照合する。**直して照合し直すのは、2回まで**。
- checker が WebFetch を使えず「開けなかった」と返したときは、こちらで `web-fetch` エージェントで URL を開き、ページの本文（原文のまま。どの URL の本文かを添えて）を依頼文に付けて、もう一度頼む。**この頼み直しは、上の2回に数えない**（開けなかったのは、エージェントの判断の問題ではないため）。こちらでも開けなければ、手順「Web のページを開く」のとおり、止めて報告する。

2回の照合を終えても指摘が残る項目は、`draft` のまま残して、報告に理由を書く。**この項目も、③・④ を行う**（スキーマで全言語・全モードの文が必須なので、YAML の形を保つため）。`status` は `draft` のまま。

## ③ 派生版

② を終えたおとな向けの日本語から、こども向けの日本語・英語・中国語を作る。② を通らず `draft` に残った項目も、同じように作る（スキーマで全言語・全モードが必須で、YAML の形を保つため。`status` は `draft` のまま）。**新しい事実（数字・時期・名前・由来・順位）を足さない**（writing.md 2）。モードの書き分け・英語・中国語（簡体字）の決まりは writing.md 4・5。文字数は 6。

- こども向けの日本語にも、`pnpm content:furigana` を使う。
- 英語・中国語に、ふりがなの記法や `{ }` は書かない。
- 派生版を作っていて、おとな向けの日本語に足りない事実が欲しくなったら、まずおとな向けの日本語に足し、出典を確かめ直す（② をやり直す）。

## ④ 検証

`gotouchi-derivative-checker` エージェントに、YAML のパスと対象の項目を渡す。報告の「指摘」を直す。

- 派生版で足した事実 → 削る（おとな向けの日本語に必要な事実なら、② からやり直す）。
- ふりがなの読みの誤り → 公式の表記で確かめて直す。検証エージェントは `pnpm content:furigana --check <YAML>` で、YAML の読みと辞書の読みの違いを見つけて報告する。自分でも、直した後に実行して、違いが残る語を確かめる（辞書が誤っていることもある）。
- 文字数・翻訳・簡体字 → writing.md の決まりに合わせて直す。
- **直して検証し直すのは、2回まで**。

## 仕上げ

1. `pnpm content:validate` を実行する。誤りがあれば直す（誤りが残るとビルドが止まる）。警告は、直すか、理由を報告に書く。`pnpm lint:yaml`（yamllint）も通す。
2. ② と ④ を通った項目の `status` を `verified` にする。通らなかった項目は `draft` のまま残す。`reviewed` にはしない。
3. 終わった時刻を控える。

## 報告

最後に、次を書く。

- 項目ごとの状態（`verified`／`draft`）と、`draft` のままの理由
- 残った警告と、その理由
- 要確認の読み（公式の表記で確かめられなかった語）
- ② と ④ の指摘の件数と、直した回数
- 開いた出典の URL の一覧（項目ごと。開いて確かめたものだけ）
- かかった時間（①〜④の合計）

## 守ること

- 出典は、実際に開いて内容を確かめられた URL だけ（9.3）。確かめられないものを、もっともらしく書かない。
- 出典の文章を写さない。
- 検証エージェント（②・④）は報告だけを返す。直すのは、このスキルを動かしている側。
- 画像・特定の店や商品の宣伝・最上級や順位を出典なしで書くこと、は避ける（writing.md 9）。
- 1つの県のファイルだけを書き換える。ほかの県・`content/guidelines/`・スキーマは変えない。
- エージェント（`gotouchi-source-checker`・`gotouchi-derivative-checker`）の指示を直したら、`evals/` の誤りを入れた YAML で評価をやり直す（やり方は `evals/README.md`）。
