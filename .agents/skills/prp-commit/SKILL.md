# 対象を選んでコミットする

`AGENTS.md`、`.codex/rules/index.md`、Git・レビュー・セキュリティ・hooksのルールを読む。コミットの依頼範囲だけを扱い、push・PRは実行しない。

1. `git status --short`、未ステージとステージ済みの差分、新規ファイルの中身を確認する。変更がなければ終了する。追加・変更・削除・未追跡の概要を示す。
2. ユーザーの対象指定を解釈する。

   | 指定 | 対象 |
   | --- | --- |
   | なし | 依頼の範囲の全変更。共有作業では他者の変更を含めない |
   | `staged` | 現在ステージ済みの変更のみ。追加ステージしない |
   | `*.ts` など | 状態一覧と照合したパターン一致ファイル |
   | テスト以外 | テストを除いた対象ファイルを最初から選ぶ |
   | 新規ファイルだけ | 未追跡ファイルのみ |
   | 自然言語・ファイル名 | 状態と差分から該当するファイルを特定 |

3. 選択したファイルと理由を示し、`git add -- <対象パス>` でステージする。ファイル名は安全にクォートし、一覧処理は空白・改行を壊さない方法を使う。無条件の全追加や、除外のためのresetで既存ステージを壊さない。混在したファイルは対象hunkだけ選ぶ。
4. `git diff --cached --stat` と `git diff --cached` を確認する。空なら対象なしとして終了。既存の無関係なステージがあればコミットへ混ぜず、内容と選択肢・推奨理由を示して判断を求める。勝手に取り消さない。
5. 変更に必要な検証・レビューと秘密情報の検査結果を確認する。hooksが失敗したら原因を直し、対象と差分を再確認する。検査回避や自動amendはしない。
6. `<type>: <日本語の説明>` の1行でコミットする。typeは `feat` / `fix` / `refactor` / `docs` / `test` / `chore` / `perf` / `ci`。変更内容を簡潔に述べ、原則72文字未満・末尾の句点なし。Claudeの署名を転記しない。`git commit -m` へ渡す本文はシェル展開されないよう扱う。

コミット後に短いハッシュ、メッセージ、変更ファイル数、残る作業ツリーの状態を報告する。次に必要ならレビュー、push、`prp-pr` を案内する。失敗時は失敗の理由と未完了を報告し、成功扱いにしない。
