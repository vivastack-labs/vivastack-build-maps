# 計画を実行する

`AGENTS.md` と `.codex/rules/index.md`、開発・実装・テスト・レビュー・セキュリティ・Git・hooksの該当ルールを読む。入力は実装計画へのパス。計画を全て読み、概要、参照パターン、担当ファイル、順序、検証、完了条件を抽出する。存在しない・不十分な計画は理由を示し、`prp-plan` での作成・補完を案内する。

## 準備

- `git branch --show-current` と `git status --short` で作業場所と既存差分を確認する。対象の作業ブランチ・worktreeを使い、他者の変更を保持する。main上なら依頼範囲内で作業ブランチを作る。未整理の変更で安全に進められなければ判断をメインへ戻す。勝手にstash・resetしない。
- `package.json` の実在するスクリプトと `.nvmrc` を確認し、pnpmを使う。自動pull・rebase・履歴書換えは行わない。同期が必要なら状態と解決案を示す。
- 仕様・要件ID・該当アーキテクチャ、各作業の `MIRROR` を読み、Next.jsコードの前にはインストール版の同梱資料を読む。
- Claude由来の計画は参照のみとする。`.codex/plans/` に出典を記した作業用計画を作り、以後の進捗・変更・完了はそちらへ記録する。元計画を更新・移動しない。
- 例外として、Claude Code から引き継いだタスク（`.handoff/HANDOFF.md` の持ち主が `codex`）の計画は、`.claude/PRPs/plans/` の元の場所のまま進捗・変更を記録し、`.codex/plans/` に写しを作らない（1タスクの計画を2つにしないため。`docs/claude-codex-collab-design.md` 6.2）。移動・改名はしない。

## 実装と検証

依存順に作業し、利用可能なら `.codex/agents/task-implementer.toml` など実在する担当定義を読んで委譲する。定義のファイル名は `.codex/agents/` で確認する。委譲不可ならメインで同じ手順を行い、その制約を報告する。

1. 仕様を観測する要件ID付きテストを先に書き、意図した失敗（Red）を確認する。
2. `MIRROR`、`IMPORTS`、`GOTCHA` に沿う最小実装でGreenにし、Refactorする。文書のみの変更は構文・参照を検証する。
3. 各変更の後に計画の局所検証と型検査を行う。失敗を直してから次の作業へ進む。期待値を根拠なく弱めず、原因を修正して再実行する。
4. 完了作業を報告し、計画との差は何を・なぜ変えたか記録する。承認範囲内の判断は進め、仕様・範囲を変える判断は既存指示で決まるか確かめてから必要分だけ確認する。

最終検証は静的解析（`pnpm typecheck`・`pnpm lint`）、該当単体テストと必要な全体テスト（`pnpm test`）、`pnpm build`、必要な統合・E2E、計画の境界条件を順に確認する。部分テストは `pnpm vitest run <path>`。カバレッジは全体80%以上・ドメイン90%以上。formatterの設定は変えず、自動修正は担当範囲に限定する。

CSPはインラインstyle・scriptを増やさず、本番ビルドのWorkers配信かE2Eで確認する。E2Eのフィクスチャ・準備待ち・タグ・ポートはAGENTSに従い、架空のhealth APIを追加しない。起動した自分のサーバーだけ終了する。UI・ルーティング変更はmerge前の手動E2E対象として記録する。外部workflow実行や画像pushはその操作まで依頼されている場合だけ行う。

コードレビューと必要なセキュリティレビューは `.codex/agents/` の専門役定義に従う。CRITICAL・HIGHを解消し、修正後に必要な再検証をする。独立レビューの有無、実行できない検証と理由を明記し、未検証を成功扱いにしない。

## 報告と成果物の整理

`.codex/reports/<plan-name>-report.md` に次を記録する。

- 実装概要、元計画・元PRD、複雑さ・確信度・ファイル数の予測と実績
- 作業別の完了状態、静的解析・単体・ビルド・統合・境界条件の結果とコマンド
- 変更ファイル・追加削除行数、計画との差と理由、問題と解決、テストファイル・件数・確認したカバレッジ
- レビュー結果、未確認事項、残作業と次の行動

完了条件を満たしたときだけCodex側PRDのフェーズを `complete` にし、報告リンクを付ける。Codex側の作業計画は `.codex/plans/completed/` へ整理し、参照リンクも合わせる。既存ファイルへ上書きしない。Claude側の元計画・PRDはそのまま残す（引き継いだタスクの計画も `completed/` へ移さず、元の場所で実際の内容に合わせるだけにする）。未完了なら計画を完了扱いにせず、阻害要因と残作業を報告する。

最終回答に計画・報告のパス、ブランチ、完了条件、検証結果、差分、PRD進捗を示す。レビュー・`prp-commit`・`prp-pr` の必要な次の手順を案内するが、この実装依頼だけでコミット・push・PR・デプロイしない。hooksを回避しない。
