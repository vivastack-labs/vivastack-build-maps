# Update Codemaps

共通規約は `AGENTS.md` と `.codex/rules/index.md`、作業に該当するルールを読む。
入力はスキル名に続くユーザーの依頼文として解釈する。Claude用の引数展開には依存しない。
Claude側の設定・資源は変更しない。回答と成果物は日本語にする。

元の `.claude/commands/update-codemaps.md` のCodex版。

1. rgでapp・src・scripts・geo等を調べ、入口、コンポーネント、状態、データと依存を追う。
   該当する `docs/architecture/` を先に読み、そこを正として矛盾させない。
2. 既存のコードマップの場所を使い、なければ `docs/CODEMAPS/` に作る。
   architecture.md（全体）、frontend.md（ページ・部品・状態）、data.md（YAML・地図データ）、
   dependencies.md（外部ライブラリ・連携）など実在する構成だけを書く。
   バックエンドがなければbackend.mdやDBの説明を作らない。
3. 1ファイル約1000トークン以内を目安に、ファイルパス・関数の契約・流れを記す。
   大量のコードは写さず、簡潔なMermaidか矢印でデータの流れを示す。
4. 既存ファイルは差分を計算し、追加削除行数／旧本文の行数（空なら新規扱い）を変更率とする。
   30%超なら候補を一時ファイルに保存して差分と理由を示し、上書き前に確認する。
   推奨は実コードと一致する候補への更新（理由：古い構成が後続作業を誤らせるため）。
   既に同じ範囲を承認済みなら確認を重ねない。
5. 生成日・調査ファイル数・推定トークン数をHTMLコメントに書く。
   `.reports/codemap-diff.txt` に追加・削除・変更、依存の増減、構造変更、90日以上古い文書をまとめる。
6. Markdown・参照先の存在を確認し、変更率・更新結果・未確認範囲を報告する。
