# 地図データ（geo/）

国土数値情報の行政区域データ（N03）から、アプリが使う2種類の TopoJSON を作る（開発概要書 第8章、7.4。T1-04）。
変換は**手で実行する**。毎回のビルドでは動かさない。出力はコミットする。

| 出力 | 内容 | 使い方 |
|---|---|---|
| `public/geo/muni/01.topo.json`〜`47.topo.json` | 県ごとの市区町村（政令指定都市は区）の形と、名前・読みがな・ローマ字。オブジェクト名は `municipalities` | 県を最大化したときに読み込む（`/maps/geo/muni/` で配信） |
| `geo/data/prefs.topo.json` | 47都道府県の形と、県名ラベルの位置（経緯度）。オブジェクト名は `prefectures` | ビルド時に SVG のパスにして HTML に埋め込む（配信しない） |

形と県名ラベルの位置は経緯度のまま入れる。投影と沖縄の別枠への移動は、描くときに `src/features/map/projection.ts` で行う（6.6 (1)）。

## 手順

Node.js・pnpm の準備はリポジトリの `AGENTS.md` のとおり。原データ（`geo/downloads/`）はコミットしない（`.gitignore` の `downloads/`）。

```bash
# 1. N03 2026年版（全国、803,201,348 バイト）を取得して、市区町村の Shapefile だけを展開する
mkdir -p geo/downloads/N03-2026 geo/downloads/soumu
curl -fsS -o geo/downloads/N03-20260101_GML.zip \
  https://nlftp.mlit.go.jp/ksj/gml/data/N03/N03-2026/N03-20260101_GML.zip
sha256sum geo/downloads/N03-20260101_GML.zip
# 1f714fca019e22e6f84012dba420384fc7b49c6ad8bd0a867ab1cfb593a78477
unzip -o -q geo/downloads/N03-20260101_GML.zip 'N03-20260101.*' -d geo/downloads/N03-2026

# 2. 総務省の全国地方公共団体コード（令和6年1月1日更新）
curl -fsSL -o geo/downloads/soumu/000925835.xlsx https://www.soumu.go.jp/main_content/000925835.xlsx
sha256sum geo/downloads/soumu/000925835.xlsx
# 7d04c8a7f6a6e76a7823a0414a8422bf2b26bb6070766971df76eab58ea6ff78

# 3. 変換する（約35秒）。県ごとの gzip 後の大きさを表示する
pnpm geo:build
```

展開した Shapefile の sha256（T1-04 で使ったもの）：

| ファイル | sha256 |
|---|---|
| `N03-20260101.shp` | `6325d7f08c9374198e27b2cffd01bd420411be8b3cf3528da0587c6cea35538d` |
| `N03-20260101.dbf` | `2d2692800f8261243b281708dc99b89e7a7bd9ba8d8674bec14e7dcf47575911` |
| `N03-20260101.shx` | `62e0a234588c44eec98778808602e94af90af2d3f85d18ab8bcabd38c5d36751` |

同じ入力と同じ版の mapshaper（`package.json` で固定）なら、何度実行しても同じ出力になる（T1-04 で、2回実行して全ファイルの sha256 が一致することを確かめた）。

## 変換の中身

`geo/scripts/build-geo.ts`（入出力）と `geo/scripts/lib/`（処理）。mapshaper は `applyCommands` で使う。

1. **市区町村**：所属未定地を除き、`N03_007`（団体コード）ごとに形をまとめる（島などで1つの市区町村が複数の形に分かれているため）。簡略化して、県ごとに分ける。属性は `code`・`name.ja`・`name.en`・`kana`・`cityName`（政令指定都市の区だけ）に差し替える。
2. **都道府県**：N03 の形を県ごとにまとめる（`N03-20260101_prefecture` は使わない。市区町村の形から作るほうが、市区町村の境界とずれない）。島ごとの形に分けて 1km² より小さな島を除き、簡略化してから県ごとにまとめ直し、県名ラベルの位置を付ける。所属未定地も含める。
3. 属性の差し替えのあと、オブジェクト名をそろえ、コードの順に並べて書く（mapshaper の出力の順に頼らない）。
4. 総務省のコード表の市区町村（区に分かれる政令指定都市の行を除く）と、N03 の市区町村のコードが一致しなければ止める（`assertSameCodes`。合併・新設の取りこぼしを見つけるため）。1県分の市区町村データが gzip 後に 100,000 バイトを超えたら、書かずに止める（開発概要書 5.1）。市区町村のファイルと都道府県の形が、どちらも 01〜47 を過不足なく持たないときも止める（前回のファイルを消す前に）。

### 簡略化の度合い（D34）

| 対象 | 簡略化 | 量子化 | 結果 |
|---|---|---|---|
| 市区町村 | `interval=100`（100m）、`keep-shapes` | 50,000 | 最大は北海道 84,262 バイト（gzip -9）。47県の合計は約1.06MB |
| 都道府県 | 1km² 以上の島だけを残す（`-explode`・`-filter-islands min-area=1000000`）、`interval=1000`（1km）、`keep-shapes` | 100,000 | `prefs.topo.json` は 151,003 バイト、gzip で約52KB（配信しない）。形は全国で467。`projection.ts` の投影で SVG のパス（小数1桁）にすると gzip で約44KB |

- 簡略化は割合ではなく距離で指定する。割合は元の点の密度で結果が変わるが、距離なら年1回の更新でも同じ意味の値になる。
- 市区町村の 100m：神奈川県を最大化した大きさ（幅900px）や、23区を画面いっぱいにした大きさで描いても、角ばりが目立たない。50m では北海道が 100KB を超える。
- 都道府県の 1km：HTML に埋め込むので、最初の読み込み（5.1、300KB 以下）に効く。全国の表示（1px ≒ 2km）では見分けられない。T1-04 の試算では、500m なら SVG は約68KB。値は `geo/scripts/lib/geo-build.ts` の `GEO_BUILD_SETTINGS` にあり、T2-04 で HTML 全体を測って見直せる。
- `keep-shapes` が守るのは形（feature）ごとに1つの輪だけで、1つの形の中の小さな島は簡略化で消える。市区町村は1つの市区町村が1つの形で、100m の簡略化なので、消えるのは岩礁ほどの島だけ。
- 都道府県は、県ごとに1つの形にまとめてから 1km で簡略化していたため、幅が1kmに満たない島がほとんど消えていた（全国で174の形しかなく、母島・南鳥島・彦島などがなかった）。そこで、島ごとの形に分けてから簡略化し、県ごとにまとめ直す。
- 都道府県に残す島は 1km² 以上にする。それより小さな島は全国の表示で1pxに満たず、県を最大化すると市区町村の形で描かれる。すべての島（約25,700）を残すと、SVG のパスは gzip で2倍以上になる。1km² 以上なら約1.1倍（形は174 → 467、gzip で約39KB → 約44KB）。
  - 例外：2つ以上の市区町村にまたがる島は、県ごとにまとめた後も境界の線が分かれたままなので、`-filter-islands` の対象にならず、1km² 未満でも残る。全国の表示では1pxに満たないので、そのままにしている（`-clean` で線を作り直すと、ほかの形まで変わるおそれがある）。
  - 残した島も 1km で簡略化するので、元は 1km² 以上でも、細い三角形（0.5km² 未満）になるものがある（全国で約45）。全国の表示では見えない。県を最大化したときは、市区町村の形（100m）で描く。
- 都道府県と市区町村で度合いが違うので、県を最大化したとき、その県（市区町村の形で描く）と、周りの県（都道府県の形で描く）の境界が最大で約1kmずれる。描き方は T2-08 で決める。

### 所属未定地の扱い（D34）

市区町村名が「所属未定地」、コードが `NN000` の形（7都県・141。東京都123、鹿児島県12、愛知県2、千葉県・和歌山県・福岡県・沖縄県が各1）は、市区町村ではないので**市区町村のファイルには入れない**。**県の形には含める**。最大化したときは県の形を下に描くので、穴にはならない。市区町村の数（1,898）は総務省のコード表の件数と一致する。

### 名前・読みがな・ローマ字

- 名前は N03 のもの。総務省のコード表は読み（カナ）にだけ使い、照合はコードで行う。コードの取り違えを見つけるため、名前も比べ、違えば止まる。字体だけが違う檮原町（N03 は「檮」、総務省は「梼」）は、`geo/scripts/lib/municipality.ts` の `SOUMU_NAME_VARIANTS` で通す。
- 読みとローマ字の作り方は開発概要書 7.4.1（D33）。政令指定都市の区の `kana` は市名を含む読み（`さっぽろしちゅうおうく`。`name.ja` の「札幌市中央区」に合わせる）、`name.en` は区だけの読みから作る（`Chuo-ku, Sapporo-shi`）。
- 北方領土の6村（`01695`〜`01700`）は、N03 と総務省のコード表の両方にあるので、北海道の市区町村として入る。
- 名前・読み・ローマ字がすべて同じ市区町村がある（北海道の泊村 `01403`（後志）と `01696`（国後島））。市区町村を引くときは、いつも `code` を使う。

### 修正表（`geo/sources/`）

総務省のカナから機械的に作ると間違うものを、団体コードで引いて直す（7.4.1）。どちらの表も `before`（直す前の値）を持ち、変換のときに今の結果と一致しなければ止まる。表のコードが地図にないとき（合併など）も止まる。年1回の更新でカナが直ったり変わったりしたとき、古い修正が黙って当たり続けないようにするため。

| 表 | 列 | 件数 | 選び方 |
|---|---|---|---|
| `kana-fixes.csv` | `code,name,before,kana` | 14 | 読みに `[きしちにひみりぎじびぴ][やゆよ]` を含む82件（区は市名を含む読みで数える）から、拗音が大きい字で書かれているものを選んだ。残りの68件（清田 きよた、千代田 ちよだ、八千代 やちよ など）は大きい字が正しい |
| `romaji-fixes.csv` | `code,name,before,stem` | 24 | 語幹（接尾辞を除いた読み）で、長音を書かない規則が母音を消す並び（お段＋う・お段＋お・う段＋う）を含む303件から選んだ |

ローマ字の選び方：母音の続きが**1つの漢字の読みの中**なら規則どおり消す（大阪 おお → `Osaka`、東京 とう → `Tokyo`、郡山 こおり → `Koriyama`、雄武 おう → `Omu`）。**漢字の境目**にまたがるなら消さない（勝浦 かつ｜うら → `Katsuura`、豊岡 とよ｜おか → `Toyooka`、勝央 しょう｜おう → `Shoo`、曽於 そ｜お → `Soo`、小海 こ｜うみ → `Koumi`）。自治体の英語名を目安にし、次は英語名に合わせた。

- 真岡市（も｜おか）：規則では `Mooka` だが、市の英語名の `Moka` のまま（直さない）。
- 山陽小野田市・周防大島町・豊後大野市：2つの地名を合わせた名前で、自治体の英語名の書き方に合わせてハイフンで分ける（`Sanyo-Onoda`、`Suo-Oshima`、`Bungo-Ono`）。

拗音を直した読み（庄内町 しょうない など）は、ローマ字も直した読みから作るので、ローマ字の表には入れない。

## 更新（開発概要書 8.4）

年1回、新しい版の N03 と総務省のコード表を取得し、上の手順の URL・ファイル名・sha256 と、`build-geo.ts` の入力のパスを直して実行する。修正表の `before` が合わない、表のコードが地図にない、総務省のコード表と N03 の市区町村が合わない、大きさが基準を超える、のどれかで止まったら、原因を確かめて表や設定を直す。

コミットした出力は `tests/data/geo.test.ts` が CI で検査する（T1-05。47県がそろっているか、項目と字、政令指定都市の区、件数、圧縮後の大きさ）。総務省のコード表は CI では読めないので、市区町村の数（1,898）と政令指定都市の数（20）はテストに定数で書いてある。変換が通ったあとで数が変わったら、テストの定数を直す（変換で総務省の表と照合済みの数）。
