# 執筆ルール

「ご当地めいぶつ日本地図」の名物・名所・行き方の文を、どう書くかの決まり。生成エージェント（T5-02）が下書きを作るときと、検証エージェント・レビュアー（[review-checklist.md](review-checklist.md)）が確かめるときに、同じものを読む。

## 1. この文書の位置づけ

- [開発概要書](../../docs/development-overview.md)の 7.2（ふりがな）・7.3（文字数）・9.3（執筆ルール）を、例つきで具体的にした文書。**食い違ったら、開発概要書が正しい**。文字数の範囲は、7.3 と `src/lib/content-rules.ts` の `LENGTH_RANGES` が正しい（この文書の表は写し）。
- 書く文は、1県につき行き方 1、名物 3、名所 3。名物と名所は、こども向け・おとな向けの解説を、日本語・英語・中国語（簡体字）で書く（7.1）。

### 機械が確かめること・人が確かめること

`pnpm content:validate`（PR の CI でも動く）と `pnpm lint`（yamllint を含む）が見つけるのは、次の表の範囲だけ。「読みが合っているか」「事実が出典と合っているか」は、CI では分からない。

| 決まり | 見つける側 | 結果 |
|---|---|---|
| 必須の項目がない・余計な項目がある。県の `code` が `01`〜`47` でない。`region` が決まった8つ以外。`id` が半角小文字の英字と `-` だけでない（数字は使えない）。`status` が `draft`・`verified`・`reviewed` 以外 | CI（`content:validate`。スキーマ） | 誤り（ビルドが止まる） |
| 名物・名所が3件でない（0件の「未作成」は許す。1〜2件は誤り） | CI（スキーマ） | 誤り |
| `emoji` がない（名物と行き方は必須。名所は任意） | CI（スキーマ） | 誤り |
| 空の文・空白だけの文 | CI（スキーマ） | 誤り |
| 出典の `url` が `https://` で始まらない。`accessed` が `YYYY-MM-DD` の形でない | CI（スキーマ） | 誤り |
| `durationMin` が1以上の整数でない | CI（スキーマ） | 誤り |

| 英語・中国語の文に、ふりがなの記法や `{ }` がある | CI（`content:validate`） | 誤り |
| 出典のタイトルの記法・存在しない確認日（`2026-02-30` など） | CI（`content:validate`） | 誤り |
| YAML の書式：`{ja: "…", en: "…"}` の括弧の内側に空白を入れない（`{ ja: "…" }` は誤り）、1行は200字まで（開発概要書 7.1 の「書式」。11. も見る） | CI（`pnpm lint` の yamllint） | 誤り（Lint が失敗する） |

| 日本語の文に、ふりがなのない漢字が残っている | CI（`content:validate`） | 警告 |
| 解説文の文字数・語数が範囲の外 | CI（`content:validate`） | 警告 |
| 出典が空（`sources: []`） | CI（`content:validate`） | 警告 |
| ふりがなの**読みが正しいか**（固有名詞を含む） | 人 | |
| 事実が出典と合っているか・出典を実際に開いて確かめたか | 人（検証エージェントも見る） | |
| 派生版（こども向け・英語・中国語）が新しい事実を加えていないか | 人（検証エージェントも見る） | |
| 語の難しさ・文体・表現の適切さ・翻訳の自然さ・簡体字か | 人 | |

警告は、ビルドを止めない。ただし、警告が残るなら理由を PR に書く（理由のない警告は直す）。

## 2. 書く順番

事実は、**おとな向けの日本語**で確定させる。ほかの版は、そこから派生させる（9.2）。

1. 出典のページを実際に開いて読み、おとな向けの日本語と出典を書く。
2. おとな向けの日本語が出典と合っていることを確かめる。
3. おとな向けの日本語から、こども向けの日本語・英語・中国語を作る。**派生版で、新しい事実（数字・時期・名前・由来・順位）を足さない**。おとな向けの日本語に書いていない事実が派生版にあれば、その事実を、まずおとな向けの日本語に足し、出典を確かめる。

## 3. 出典

- 残す出典は、**実際に開いて内容を確かめられた URL だけ**。確かめられなければ `sources: []`（画面には「出典なし」と出る。CI の警告）。
- 優先順位：
  1. 自治体・観光協会の公式サイト
  2. 公的機関の一覧（農林水産省「うちの郷土料理」、経済産業大臣指定の伝統的工芸品など）
  3. それ以外
- 出典の文章を写さない。読んで、自分の言葉で要約する。
- `title` は、出典のページに表示されている題名のままにする（日本語の題名にふりがなは付けなくてよい）。題名に `{` `}` が含まれると、ふりがなの記法として検査されて誤りになる。そういう題名にあたったら、PR に書いて相談する。
- `accessed` は、**実際に開いた日**（実在する `YYYY-MM-DD`）。
- 確かめた出典があれば、1つの項目に1〜3件。同じ内容の出典を、数だけ増やさない。

```yaml
sources:
  - title: "（出典のページの題名のまま）"
    url: "https://..."
    accessed: "2026-11-11"
```

## 4. モードごとの書き方

| | こども向け（`kids`） | おとな向け（`adult`） |
|---|---|---|
| 読む人 | 小学校中学年 | 大人 |
| 中心 | 理由や体験（何がすごいか、どう楽しむか） | 事実を1つ加える（時期・地域・由来・数値など） |
| 語 | 小学校中学年が読める語。難しい語は、やさしい言い方に言い換える | 出典の用語を使ってよい |
| 日本語の文体 | 話し言葉（「〜だよ」「〜なんだ」） | 「です・ます」 |

- こども向けでも、事実を変えない。やさしくするのは、語と言い方だけ。
- こども向けの文は、1つか2つの短い文にする。文字数の範囲（6.）に収まらなければ、ひとつ削る。
- 数字は、おとな向けに書いてよい。こども向けに書くときは、おとな向けと同じ数字にする（数字を丸めたり、言い換えたりして、別の数字にしない）。

## 5. 言語ごとの書き方

### 日本語

- 漢字には**すべて**ふりがなを付ける（`{漢字|よみ}`。7.2）。付け忘れは CI の警告。
- ルビを付ける単位は**語ごと**。`{収穫|しゅうかく}`、`{北海道|ほっかいどう}`。語の中の漢字ごとに分けない（`{収|しゅう}{穫|かく}` としない）。送り仮名が語の途中にある語は、漢字のかたまりごとに分ける（`{焼|や}き{魚|ざかな}`、`{乗|の}り{換|か}え`）。
- **送り仮名は括弧の外**に出す：`{広|ひろ}い`、`{育|そだ}って`。
- ふりがなは、`pnpm content:furigana "文"`（標準入力の各行でもよい）で自動で付けられる。付いていない漢字にだけ付き、すでにある `{漢字|よみ}` は変えない。標準エラーに出る「要確認」の語（固有名詞・辞書にない語・送り仮名で区切れなかった語に加えて、漢字の続きが2つ以上の語に分かれた複合語〔紋織物・西軍など。分かれた読みが誤りやすい〕と、数字の後の漢字〔11月・3日など。月・日・年・社・本などは数え方で読みが変わる〕）は、次の項目のとおり、読みを公式の表記で確かめて直す。`pnpm content:furigana --check <YAML のパス>...` は、YAML に書いた `{漢字|よみ}` の読みを辞書の読みと比べて、違うものを出す（YAML は読むだけ。辞書が誤っていることもあるので、違いは、どちらが正しいかを公式の表記で確かめる）。
- 読みに使える字は、ひらがなと長音記号「ー」だけ（カタカナ・空白は誤り）。
- 熟字訓（`{今日|きょう}` など、字ごとに読みを分けられない語）は、語全体に付ける。
- 同じ語が文に何回出ても、そのたびに付ける。
- 数字（`1`・`2`…）は、そのままでよい。漢数字（`一`・`二`）は漢字なので、ふりがなを付ける。
- 地名・人名・施設名の読みは、自動でふりがなを付けたときに間違えやすい。**公式サイトの表記で確かめる**（読みの正しさは CI では見つからない）。

### 英語

- 同じモードの日本語の意味を訳す（逐語訳にしない。英語として自然な語順にする）。新しい事実を足さない。
- 県名・市区町村名などの地名は、**マクロンなしのヘボン式**（`Tokyo`・`Kyoto`・`Hokkaido`）。県名・県庁所在地の `name.en` とそろえる。
- 空港・駅・施設・山などは、公式サイトの英語表記を使う（`New Chitose Airport`・`Mount Hakodate`）。公式の表記がないときは、開発概要書 7.4.1 の規則（マクロンなし、「ん」は `n`、長音を書かない）のローマ字にする。
- 日本語の語（`ikura`・`sushi` など）を使うときは、短い説明を添える（`salmon roe called ikura`）。
- ふりがなの記法や `{ }` は書かない（誤り）。
- 英語の文字数は**語数**で数える（6.）。

### 中国語

- **簡体字**で書く（D7）。繁体字（`寬闊`・`收穫`）にしない。
- 同じモードの日本語の意味を訳す。新しい事実を足さない。
- 日本の固有名詞は、中国語で定着した表記があればそれを優先して使う（`东京`・`北海道`）。定着した表記が分からないときは、日本語の漢字を簡体字に直した形にする。
- ふりがなの記法や `{ }` は書かない（誤り）。

## 6. 文字数

7.3 の表の範囲に収める。範囲の外は CI の警告だが、**収めるのを基本にする**。収められない理由があれば、PR に書く（たとえば、固有名詞が長く、削ると意味が変わる場合）。

| | こども ja | おとな ja | こども en | おとな en | こども zh | おとな zh |
|---|---|---|---|---|---|---|
| 名物 | 20〜35字 | 30〜50字 | 10〜20語 | 12〜25語 | 15〜30字 | 20〜40字 |
| 名所 | 15〜25字 | 25〜40字 | 8〜15語 | 8〜18語 | 12〜22字 | 15〜30字 |

数え方（`countLength`）：

- 日本語：ふりがなを除き、空白を除いた字数。**句読点・記号も1字**と数える（`、` `。` `！` など）。
- 中国語：空白を除いた字数。句読点・記号も1字と数える。
- 英語：空白で区切った語数。`-` でつないだ語は1語、単独の記号（`→` など）も1語。

## 7. 名前と絵文字

- 名前（`name`）は短く、カードの1行に収まる形にする。ふりがな（日本語）は同じ決まり。英語は 5. の地名の表記。
- 名物と行き方には絵文字（`emoji`）が必須。名所は付けても付けなくてもよい。**絵文字は、品物や場所の見た目をひとつ選ぶ**。複数並べない。
- 使ってよい絵文字は、**Emoji 12.0（2019年）までに入った絵文字**。**ZWJ で組み合わせた絵文字・国旗は使わない**。Windows 10 の標準の絵文字フォントは Emoji 12.0（2019年）までで、それより新しい絵文字は表示されないため（学校の端末に Windows がある。5.3・D25）。
- 確かめ方：Emojipedia で、その絵文字の Emoji のバージョンを確かめる（12.0 以下ならよい）。
- 画像は使わない（9.3）。

## 8. 行き方

東京からの行き方（`access`）も、同じ決まりで書く。

- `emoji` は、交通手段の絵文字を1つ（`✈️`・`🚄` など。7. の範囲で）。
- `mode`（交通手段）は短い語（`{飛行機|ひこうき}`・`{新幹線|しんかんせん}`）。`route` は乗り物・駅・空港の名前を、`→` でつなぐ。駅・空港の名前は、公式の表記と読みで確かめる。
- `durationMin`（所要時間）は**目安**（1以上の整数の分）。ダイヤが変わると変わるので、出典（交通機関の公式の情報）の数字を使う（R2：年1回見直す）。
- 出典の区間ごとの時間を足すのはよい。足したときは、内訳と、乗り換えの待ち時間を含めたかを PR に書く。出典にない時間を見積もって足さない。画面には「目安」と出る。

## 9. 避けること

- 特定の店・商品・宿の名前を出して、勧めること（宣伝）。
- 「日本一」「世界一」「最も」などの最上級や順位を、**出典に書かれていないまま**書くこと。出典にあっても、いつの・何についての順位かが分からない書き方にしない。迷うときは、順位でなく、事実（時期・場所・由来）を書く。
- 季節が限られる名物・名所を、一年中あるように書くこと。時期（`秋に`・`春は`）を添える。
- 断定できないこと（「必ず」「絶対」「すべての」）。
- 出典の文章をそのまま、または語尾だけを変えて写すこと。

## 10. 例

> **この節の例は、書き方の例です。出典を確かめた内容ではありません。コンテンツ（`content/prefectures/`）に写さないでください。** 事実として使いたいときは、出典を実際に開いて確かめ直してから、書き直す。

例の文字数・語数は、`countLength` と `checkRuby` で確かめた（良い例はすべて範囲の中・ふりがなの誤りなし。悪い例は、示した誤りだけが出る）。題材は北海道の「じゃがいも」（名物）と「函館山」（名所）。

### 10.1 良い例：名物「じゃがいも」

`name`：`ja: "じゃがいも"`、`en: "Potatoes"`、`zh: "土豆"`。`emoji: "🥔"`。

| モード | 言語 | 文 | 数 |
|---|---|---|---|
| こども | ja | `{広\|ひろ}い{畑\|はたけ}で{育\|そだ}って、{秋\|あき}にとれるおいもだよ。{全国\|ぜんこく}の{町\|まち}へ{届\|とど}くんだ。` | 29字（20〜35） |
| おとな | ja | `{涼\|すず}しい{気候\|きこう}を{生\|い}かして{広\|ひろ}い{畑\|はたけ}で{育\|そだ}てられ、{秋\|あき}に{収穫\|しゅうかく}されて{全国\|ぜんこく}へ{出荷\|しゅっか}されます。` | 36字（30〜50） |
| こども | en | Potatoes grow in wide fields, are dug up in autumn, and are sent all over Japan. | 16語（10〜20） |
| おとな | en | Grown in wide fields that make use of the cool climate, potatoes are harvested in autumn and shipped all over Japan. | 21語（12〜25） |
| こども | zh | 土豆在宽阔的田地里长大，秋天就能收获，还会送到全国各地。 | 28字（15〜30） |
| おとな | zh | 利用凉爽的气候，在宽阔的田地里种植土豆，秋天收获后运往全国各地。 | 32字（20〜40） |

- おとな向けの事実は「涼しい気候」「秋の収穫」（時期と条件）。こども向けは、同じ事実を「広い畑で育つ」「秋にとれる」「全国の町へ届く」と、やさしく言い換えた。おとな向けにない量の語（「たくさん」・`lots of`・`很多`）は足していない。新しい事実はない。
- 英語・中国語は、同じモードの日本語を訳した（語順は、それぞれの言語で自然な形に変えてある）。

### 10.2 良い例：名所「函館山」

`name`：`ja: "{函館山|はこだてやま}"`、`en: "Mount Hakodate"`、`zh: "函馆山"`。

| モード | 言語 | 文 | 数 |
|---|---|---|---|
| こども | ja | `{山\|やま}の{上\|うえ}から、{夜\|よる}のまちがきらきら{光\|ひか}るのが{見\|み}えるよ。` | 24字（15〜25） |
| おとな | ja | `ロープウェイで{山頂\|さんちょう}へ{上\|のぼ}ると、{港\|みなと}と{市街地\|しがいち}の{夜景\|やけい}を{一望\|いちぼう}できます。` | 30字（25〜40） |
| こども | en | From the top of this mountain, you can see the town glitter at night. | 14語（8〜15） |
| おとな | en | Take the ropeway to the summit for a sweeping night view of the harbor and the city. | 17語（8〜18） |
| こども | zh | 从山顶上，可以看到夜晚闪闪发光的城市。 | 19字（12〜22） |
| おとな | zh | 乘坐缆车登上山顶，可以将海港和市区的夜景尽收眼底。 | 25字（15〜30） |

- おとな向けの事実は「ロープウェイで山頂へ上る」（行き方）。こども向けは、見える景色（体験）を中心にした。

### 10.3 悪い例と、直し方

悪い例は、すべて作り物。主な誤りを1つずつ見せる。

| # | 誤り | 悪い例 | なぜ悪いか | 見つかる所 | 直した例 |

## 11. YAML の書き方

ふりがなを付けた日本語の文は長くなる。YAML の書き方で、文に余計な空白を入れたり、書式の検査（yamllint。`content/.yamllint`）に落ちたりしやすい。

- 日本語の文は、`>-` や `|` を使わず、**`"…"` で囲んで1行に書く**。`>-` は、行の折り返しの改行が空白1つになり、日本語の文の途中に空白が入るため。
- 1行は **200字まで**（`content/.yamllint`）。200字を超えるときは、`"…"` の中で**行の終わりに `\` を書いて、次の行に続ける**。`\` で続けた行は、空白が入らずにつながる。折り返す位置は、読点（、）の後にして、`{漢字|よみ}` の括弧の途中では折り返さない。
- 続きの行は、**キー（`adult:`）の位置より2字深く**インデントする（インデントの空白は文に入らない）。キーと同じか浅いと、`content:validate` が閉じていない `"` の誤りを出す（yamllint では見つからない）。
- `"` で囲んだ文の中に、`"` を書かない（書くなら `\"`）。
- ファイルの先頭に `---` を書く（ないと yamllint の警告。Lint は通るが、書く決まり）。インデントは2字。
- 1行のマップは、括弧の内側に空白を入れない：`{ja: "…", en: "…", zh: "…"}`（`{ ja: … }` は yamllint の誤り）。
- YAML のエイリアス（`&`・`*`）は使えない。

```yaml
specialties:
  - id: potato
    description:
      ja:
        adult: "{涼|すず}しい{気候|きこう}を{生|い}かして{広|ひろ}い{畑|はたけ}で{育|そだ}てられ、\
          {秋|あき}に{収穫|しゅうかく}されて{全国|ぜんこく}へ{出荷|しゅっか}されます。"
```

上の例（実際のファイルの深さ。`adult:` が8字目、続きの行が10字目）は、`yaml` パッケージで読むと、`{育|そだ}てられ、{秋|あき}に…` と空白なしにつながる（10.1 のおとな ja と同じ文。実際には1行に収まる長さだが、`\` の使い方を見せるために折り返した）。

## 12. 書き終えたとき

次を順に確かめてから、PR に出す。

1. `pnpm content:validate` と `pnpm lint` を動かし、誤りがないこと。警告は、直すか、理由を PR に書く。
2. おとな向けの日本語が、出典と合っていること。
3. 派生版に、新しい事実がないこと。
4. 日本語の固有名詞の読みを、公式の表記で確かめたこと。
5. `status` は、下書きなら `draft`、検証エージェントが確かめたら `verified`。**`reviewed` にするのは、レビューの承認の後**（[review-checklist.md](review-checklist.md)）。
