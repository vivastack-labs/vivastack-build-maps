# テスト

- ロジックや振る舞いの変更は Red → Green → Refactor。要件IDのあるテストを先に書き、
  意図した理由で失敗することを確かめてから実装する。
- 単体・コンポーネント・データ・E2Eから、その振る舞いを観測できる層を選ぶ。
  文書や指示だけの変更には、文言を固定するだけのテストを増やさず、構文・リンク・実際の読み込みを確認する。
- カバレッジは全体80%以上、ドメインロジック90%以上。対象と強制条件は `vitest.config.ts` を正とする。
- 部分実行は `pnpm vitest run <path>`、全体とカバレッジは `pnpm test`。
- テスト失敗時は分離・モック・実装を調べる。期待値が誤っている根拠なしにテストを弱めない。
  Arrange → Act → Assert の流れで意図を明確にする。
- async Server Component は E2E、純粋なロジックは単体で検証する。
  E2E のフィクスチャ、準備待ち属性、`@pc` / `@touch` のタグは `AGENTS.md` に従う。
- CSPを含む動作は `pnpm build` と Workers 配信、または E2E で確認する。
- UI・ルーティングを変更したPRは merge 前に手動 E2E workflow の成功を確認する（D30）。
  開発中のPRごとの自動実行へ変更しない。
