# 開発の流れ

1. タスク定義・仕様の該当章・要件ID・設計判断・アーキテクチャを読む。
   既存コード・テストを `rg` で調べ、再利用できる実装を探す。
   ライブラリを使う判断にはインストール版の資料、Context7や一次資料を使う。
   外部調査は不足する情報に絞り、ツールが使えなければ利用可能な一次資料へ切り替える。
2. 開発計画のタスクへの着手を頼まれたら `.agents/skills/next-task/SKILL.md` を使う。
   実装計画は `.codex/plans/<タスクID>-<slug>.plan.md` に残す。
   既存の `.claude/PRPs/plans/` は参考に読めるが、Codex の作業で書き換えない。
3. 実装計画の承認が必要なタスクでは、要点・判断事項・推奨案と理由をすべて示す。
   既に承認された範囲や日常的な実装判断のために確認を繰り返さない。
4. TDDで実装し、仕様との差は `docs/development-plan.md` 1.3 に従って扱う。
   オーナーの判断が必要な変更は先に確認し、採用内容を仕様・タスク・計画に反映する。
5. 変更に見合う検証、コードレビュー、必要なセキュリティレビューを行う。
   CRITICAL・HIGH を直し、完了条件をすべて確認する。
6. PR前に計画を実際の内容へ合わせ、変更内容・判断・検証結果を日本語で説明する。
   画面変更には `pnpm screenshots` の after の表を載せる。

Claude 専用の planner / tdd-guide などの存在を仮定しない。計画と判断はメイン、
実装は `task-implementer`、レビューは専門のレビュアー、補助調査は `general-purpose` が担う。
