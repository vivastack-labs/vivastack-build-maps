# コードレビュー

- コード変更後・PR前に `code-reviewer` でレビューする。対象の差分、計画、完了条件を渡す。
  コミット前の差分と未追跡の新規ファイルも含め、周辺コード・呼び出し元を読んで判断する。
- レビュー前に必要な検証を通し、対象ブランチとの競合を解決する。
  検証が実行できない場合は成功扱いにせず、未確認の範囲と理由を明記する。
- 不具合・回帰・秘密情報・入力検証・エラー処理・テスト不足を優先する。
  単なる好みや行数の閾値だけで重大な指摘にしない。
- 認証・認可、入力、ファイル、外部リクエスト、依存関係、暗号、CI権限を変えるときは
  `security-reviewer` にも確認を依頼する。本アプリで存在しないAPIやDBは検査対象に作り足さない。

| 重大度 | 意味 | 対応 |
| --- | --- | --- |
| CRITICAL | 悪用可能な脆弱性・データ損失など | PR前に修正 |
| HIGH | 不具合・回帰・重要な要件違反 | PR前に修正 |
| MEDIUM | 保守性・性能などの問題 | 可能な限り修正 |
| LOW | 小さな改善 | 必要に応じて対応 |

本プロジェクトでは CRITICAL・HIGH が残れば完了にしない（開発計画1.1）。
修正は実装担当へ戻し、重要な指摘の修正後は再レビューする。
メインが最終的な差分と検証結果を確かめ、独立したレビューの有無も記録する。
