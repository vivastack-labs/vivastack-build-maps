# 役割分担

計画・オーナーとの判断・ブランチ操作・最終検証・PRはメインが担当する。
専門的な作業には `.codex/agents/` の定義を使う。

| エージェント | 担当 | 呼ぶとき |
| --- | --- | --- |
| `task-implementer` | 承認済み計画の TDD・レビュー修正 | `next-task` の実装 |
| `code-reviewer` | 不具合・回帰・設計・テストのレビュー | コード変更後、PR前 |
| `security-reviewer` | シークレット・入力境界・CSP・CIの権限 | セキュリティに関わる変更 |
| `general-purpose` | 範囲を限定した調査・検証・補助作業 | 他の専門役に収まらない委譲 |
| `gotouchi-source-checker` | おとな向け日本語と実際の出典の照合 | 明示的な出典検証の依頼 |
| `gotouchi-derivative-checker` | 派生版の意味・ふりがな・形式の検証 | 明示的な派生版検証の依頼 |

- 依頼には目的、担当ファイル、参照資料、完了条件、実行してよい操作を含める。
- 独立した調査・レビューは、委譲が利用可能なら並列に進める。同じファイルへの編集や、
  ビルドの `dist/` を共有する検証は並列にしない。
- レビュアーは編集しない。修正は担当した実装者に追加指示を送り、同じ文脈で続ける。
- `blocked` の判断はメインに戻す。メインは既存の承認で解決できるかを先に確かめ、
  オーナーの判断が必要な場合だけ推奨案と理由を付けて確認する。
- 子の成功報告だけで完了にしない。メインが差分と完了条件を確かめる。
- 利用可能なツールに役割名の指定欄がなければ、定義の `developer_instructions` と依頼内容を
  渡す。呼べなければメインで同じ手順を実施し、その制約を報告する。
- サブエージェントも親の権限・sandbox・hooksを引き継ぐ。委譲を権限の拡大に使わない。
