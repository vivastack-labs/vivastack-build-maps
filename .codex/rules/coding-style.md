# コーディング

- イミュータブルに書き、責務の小さい関数・ファイルに分ける。深いネストは早期 return で減らす。
  関数50行・ファイル800行は分割を検討する目安とし、意味のない分割を目的にしない。
- 単純な実装を選び、実在する重複だけをまとめる。必要のない抽象化・将来用の機能を足さない。
- 入力・外部API・ファイルの内容は境界で検証し、利用できるスキーマを使う。
  例外を握りつぶさず、利用者向けのエラーと内部の診断を分け、秘密情報を出さない。
- 変数・関数は説明的な `camelCase`、型・コンポーネントは `PascalCase`、hook は `use` で始める。
  意味のある定数に名前を付ける。
- export する関数・型・定数には JSDoc を付け、目的・前提・エラー条件・関連要件IDを書く。
  `app/` の Next.js 固有の export と自動生成ファイルの例外は `AGENTS.md` に従う。
- 該当する `docs/architecture/` を変更前に読み、実装を変えたら更新する。
  Next.js はインストール版の `node_modules/next/dist/docs/` を先に読む。
- デバッグ出力・未使用コードは残さない。formatter・lint の設定は指示なしに変更しない。
