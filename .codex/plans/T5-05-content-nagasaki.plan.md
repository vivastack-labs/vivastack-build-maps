## 作業順

1. 計画の承認後、計画をコミットする。Node.js 26 と `pnpm install --frozen-lockfile` で作業環境を用意する。
2. `gotouchi-content` を使い、[長崎県の YAML](../../content/prefectures/42-nagasaki.yaml) に公式出典を開いて確認したおとな向け日本語と東京からの行き方を書く。既存の県名・地方・県庁などを保持する。
3. 出典チェッカーへ事実と出典の独立照合を依頼し、必要な修正と再照合を行う。ふりがなは自動付与の結果を公式表記で確かめる。
4. 検証した日本語からこども向け日本語と英語・簡体字中国語の両モードを書き、派生版チェッカーに独立検証を依頼する。両方の照合と機械検査を通った項目を `verified` にする。
5. 検証結果と独立レビューを確認し、計画へ実績を記録して `develop` 向けの PR を作る。レビューの承認後の `reviewed` への変更とマージはオーナーが行う。

## 検証

| 確認事項 | 検証方法 |
| --- | --- |
| T5-05・7.1〜7.3 の項目数、全言語・モード、文字数、状態、出典の形式 | 既存の `pnpm content:validate` と `pnpm vitest run tests/data/content.test.ts` を使う。アプリの振る舞いの変更は発生しないため既存検査を適用する |
| 9.2〜9.3 の事実、出典、翻訳、ふりがな | 各検証役が項目ごとに照合する。`pnpm content:furigana --check content/prefectures/42-nagasaki.yaml` と `pnpm lint:yaml` も実行する |
| 全体の検査とビルド | `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm build:preview` を実行する。長崎県の本番カードと、プレビューの3言語の全7件・下書き表示・出典を生成物から確認する |
| 9.4 の人による承認、E2E | PR に確認結果を記載してレビューへ引き継ぐ。E2E はデータ整備後の `develop` → `main` の統合 PR で実施する |
