# T5-05 沖縄県のコンテンツ制作計画

## 対象と仕様

- `origin/develop` の `91a555a` を基点に、専用 worktree と `feat/T5-05-content-okinawa` を使う。T5-05 は既に作業中。
- [タスク定義](../../docs/tasks/m5-content.md)と開発概要書 7.1〜7.3、9.2〜9.4、R8・D22・D30、執筆ルールとレビュー基準に従う。
- [沖縄県の YAML](../../content/prefectures/47-okinawa.yaml) の基本情報を維持し、名物3件・名所3件・東京からの行き方を作る。

## 題材の推奨案

| 項目 | 候補 | 理由 |
| --- | --- | --- |
| 名物 | 沖縄そば、ゴーヤーチャンプルー、紅型 | 食文化と伝統工芸を紹介できる |
| 名所 | 首里城公園、沖縄美ら海水族館、平和祈念公園 | 歴史、海の生き物、平和を幅広く紹介できる |
| 行き方 | 羽田空港から那覇空港への直行便 | 航空会社の公式時刻表で区間と時間を確認できる |

公式出典を実際に開き、裏付けられる内容を選ぶ。施設の復元・公開状況と時刻表の対象期間は確認時点に合わせる。根拠が得られない候補は差し替える。

## 手順と検証

1. 承認後、計画をコミットし、Node.js 26・pnpm の環境を準備する。
2. `gotouchi-content` に従い、公式出典を開いておとな向け日本語と行き方を作る。出典検証役による照合後、子ども向け・英語・簡体字中国語を作り、派生版検証役に依頼する。ふりがなはツールと公式表記を照合する。
3. 両検証と機械検査を通過した項目のみ `verified` にする。人のレビュー後に判断する `reviewed` にはしない。
4. 既存の `pnpm content:validate`、`pnpm content:furigana --check content/prefectures/47-okinawa.yaml`、`pnpm lint:yaml`、データテストで書式・項目数・文字数・状態を確認する。新しいアプリの振る舞いは追加しないため、既存検査を使う。
5. `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm build:preview` を実行し、生成物で本番の絞り込みとプレビューの3言語・全項目・出典を確認する。UI の E2E はデータ整備後の統合 PR で行う。
6. 差分と完了条件の独立レビューを受け、検証結果と計画の変更を記録し、`develop` 向け PR を作る。

## 実施結果

- 出典を制作担当と出典チェッカーがそれぞれ開き、全7項目を照合した。ゴーヤーチャンプルーは原文に近い表現を直して2回目で通過し、残りは初回で通過した。
- 派生版チェッカーの指摘に従い、苦瓜の英語説明、平和の礎の簡体字と英語を修正して再検証した。独立レビューの指摘で水族館名のふりがなを区切り直し、再検証した。最終的に7項目を `verified` とした。
- ふりがなの辞書との差8件は、一般語の読みと施設・地名の公式表記、島豆腐の辞書で確認した。比較不可は0件。
- `pnpm content:validate` は47県で誤り・警告0件。`pnpm lint` と `pnpm typecheck` は成功。全体 lint に既存の YAML 警告2件がある。
- `pnpm test` は98ファイル・2,048件成功。全体カバレッジは statements 96.72%、branches 93.97%、functions 96.70%、lines 96.94%。最初の実行はサンドボックスの Git 子プロセス制限で2件失敗し、権限を変更して再実行した。
- 本番の標準ビルドは Turbopack がローカルポートの作成を拒否され失敗した。Webpack と既存の後処理による本番生成は成功し、3言語の沖縄県カードは名物・名所が空で行き方がないことを確認した。
- Webpack と既存の後処理によるプレビュー生成も成功。3言語で全7項目・出典・2モード・下書きフラグと noindex を確認した。
- 独立レビューは重大な指摘なし。水族館名のふりがな区切りに関する MEDIUM 1件は修正し、派生版検証役が確認した。
